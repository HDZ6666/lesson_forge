# 自动题库采集需求与实施方案

> 已于 2026-10-01 归档。以下为历史原文，文中的“当前”“唯一入口”“下一步”和完成状态只指当时，不用于指挥本轮实施。接手请读[文档入口](../README.md)；当前需求以[重构实施规格](../重构实施规格.md)为准，进度以[实施任务清单](../实施任务清单.md)为准。

日期：2026-09-30。状态：需求梳理与实施建议；未创建自动采集计划、未启动新采集、未修改生产调度策略。

最新需求与重构入口：[项目需求与重构清单](项目需求与重构清单-2026-09-30.md)。同步中心最终采用四个子菜单，异常合并到同步任务的“待处理问题”标签；本文保留调度分析及只读观察，界面归属以最新清单为准。

## 1. 已确认的目标与顺序

1. 当前面向自己或少量教师，第一阶段集中完成题库覆盖，教案生成暂时后置。保留已实现的教案代码及数据，不继续扩展该模块。
2. 采集程序在服务器后台自动运行，关闭页面不影响任务。
3. 可以配置“同步数学全部教材”的长期计划；每一个内容同步任务只对应一本教材，不再在单个任务中多选教材。
4. 单本或局部问题要明确展示，允许人工判断，不应因为一本教材的数据问题取消后续教材。
5. 首次覆盖全部教材，之后定期更新；新旧版本均保留，新版优先。
6. 稳定优先，全天低负载；依据资源和来源反馈降速、等待或暂停。
7. 教材总数由实际发现维护，不能固定为 151；为未来扩展其他学科保留学段/学科边界。
8. 用户进一步明确：每本先有一批可用题目，单次未抓全的合格结果也要入库；允许手动重跑或在下一轮自动补齐和更新，不能因为单次题数不足阻断整本或整轮。

第一阶段验收采用“每本具备可用题库”的基础覆盖口径，同时展示数量与目录缺口。它不等于完整扫描或抓取到来源全部题目；后续循环持续改善覆盖。

## 3. 四个核心对象，分清职责

| 对象 | 用途 |
| --- | --- |
| 教材台账 | 当前有哪些教材、来源标识、学科/学段、是否纳入计划、覆盖情况、下次到期时间 |
| 自动计划 | 范围是整个学科，控制新版优先、首次覆盖/周期刷新、运行预算、暂停与恢复 |
| 单本任务 | 一次同步一本教材，记录采集、校验、入库阶段和最终结果 |
| 执行尝试与异常 | 同一个任务的重启/续采记录、具体页/题/素材问题、人工处理结果 |

“同步全部”由计划持续派发多个单本任务实现，不再创建一个含 151 本的大任务。手动同步也只能选择一本，进入同一个调度队列，并遵守资源和来源限制。

任务是一次业务同步；尝试是一次进程执行。未结束任务的短时失败恢复沿用任务并记录尝试。已结束、已有部分结果入库的任务保持历史不变；点击“重跑/补采”创建一个关联原任务的新单本任务，下一轮周期更新也创建新任务。底层可以复用已有题目、素材和可信断点，不能把“创建新任务”等同于必须重抓所有内容。

## 4. 教材发现与动态变化

- 定期按“来源 + 学段 + 学科”刷新教材清单；刷新本身也受来源限速与冷却约束。初期建议每周发现一次，并提供手动刷新，频率可配置。
- 对稳定来源 ID 做匹配：新增自动登记并加入首次覆盖队列；改名更新展示信息；新旧版本分类依据来源字段并允许人工修正。
- 单次没有发现的旧教材先标记本次未发现，不删除题目、不撤销历史。只有完整清单刷新才可用于判断缺席，失败或截断的发现结果不能下线教材。
- 人工排除/暂停的教材保存原因，后续自动发现不得重新强制加入。未确认的异常不能自动当作排除。
- 新教材优先补覆盖，但保留旧版和长期等待教材的调度份额，避免新版持续增加导致旧版永远排不到。
- 每一轮保留当时的教材清单版本及目标数；运行中发现新增教材纳入后续待办，页面同时显示本轮目标与最新总数，避免完成率分母无解释地变化。首轮优先让所有纳入教材都有合格题目，不因某一本尚未抓全而无限重复它。

多学科不能只替换 URL。当前正式教材模型缺少明确学科维度，采集 CLI 虽可传 bank 参数，但默认仍为初中数学。需要统一来源、学段、学科、教材标识在正式库、采集库、任务、游标和素材归属中的表达，验证来源 ID 是否跨学科唯一；不能未经验证沿用全来源唯一假设。

第一阶段先跑通数学；其他学科按解析能力逐个接入并使用相应样本验证，尤其是非数学题型、音频等素材。调度共用，解析规则按学科/来源区分。

## 5. 每天几本：采用预算和反馈，而非固定产量

### 5.1 初始运行方式

同一时间先只采集一本教材。初期让少量有代表性的教材完成观察，覆盖大/小题量及新/旧版；沿用或降低已知配置，不因一次成功就提升并发。

界面可设置每天最大启动本数作为保护上限，但每天实际完成几本由请求量、运行时长、恢复等待、存储和来源反馈决定。一本教材也可能跨天续采；达到预算时在安全断点暂停，不能标记成功或从头再抓。

### 5.2 每次派发之前检查

1. 自动计划启用，教材已到期，当前无相同教材的待执行/执行中任务。
2. 同来源没有冷却或待人工解除的阻断。
3. 主机可用内存、Swap 活动、磁盘/I/O 和网站响应在预算内；磁盘要预留本次预计增长、数据库日志、备份与安全余量。
4. 今日运行时长、请求量、下载量及手工配置的本数上限尚未耗尽。
5. 待入库或待下载积压没有超过上限，避免抓取比存储处理快而挤满磁盘。

### 5.3 运行中与运行后调整

- 记录每本的成功页、重试页、429/验证事件、延迟、字节量、耗时、进程峰值和磁盘增量；不能只记录最终成功/失败。
- 请求按来源共享限速额度。未来不同学科若使用同一站点，也共享来源预算；列表 API 与素材 CDN 可分别限速，同时受宿主资源总预算控制。
- 连续稳定只允许小幅恢复到明确上限；异常立即降速或进入冷却，不以“试到被封”为调参目标。
- 使用最近同类教材的统计更新预计工作量和完成日期，显示区间及样本不足提示。此前约 70.7 分钟仅是一个样本。
- 优先顺序建议为：人工指定且已到期的任务、未覆盖新版、未覆盖旧版、已到重试时间的局部补采、到期刷新；增加等待时长权重与重试预算，避免饥饿或坏任务无限重试。
- 尚未完成基础覆盖时，优先处理没有可用题目的教材。已有部分可用题但未抓全的教材记录待补，在其他教材获得机会后进入补采队列；给失败重试设置单独预算，避免一直卡在一本书。
- 补采和正常刷新分开排期：未解决缺口在来源冷却与轮转公平允许后继续补，不等待完整教材的常规刷新周期。新版约 30 天、旧版约 90 天可作为已充分覆盖教材的初始检查周期建议，最终按来源变化率和预算调整；这些数值并未开启。

增量入库可以只更新变化，但来源若没有可靠的变更游标，不能保证只抓增量页面。应区分“少写数据库”和“少请求来源”；每轮综合检查新题、已知失败位置和未覆盖范围，并周期性核对旧范围。

来源按“最新”排序时，新题会改变分页位置。跨天重跑不能机械地从旧页码继续：应核对教材/过滤条件和排序，检查新增部分，对断点附近进行有边界的重叠扫描并按来源 ID 去重；若无法确认续采安全，则重新扫描相应目录。原有抓到的题目继续保留，不能为了追求省请求而宣称不存在漏题。

## 6. 异常如何不影响后面

| 异常范围 | 处理方式 | 对队列的影响 |
| --- | --- | --- |
| 个别图片/题目解析失败 | 有限重试，保存证据与位置；跳过问题项，继续本书后续可处理内容 | 其他教材继续；异常单独待处理 |
| 某目录分页异常、来源页数上限 | 保存断点及已扫描范围，明确缺口；必要时继续本书其他目录 | 本书为部分完成，不拖住其他书 |
| 一本教材目录结构无法识别 | 本书挂起，生成明确问题单 | 释放执行位置，继续其他可执行教材 |
| 暂时网络/5xx | 有上限的重试、退避与下次尝试时间 | 释放长等待，避免无限占用执行位置 |
| 429、验证码、来源级访问阻断 | 按响应及来源规则冷却或等待人工处理；冷却状态跨任务和重启保存 | 暂停同来源，不能切换同站其他教材继续加压；独立来源在主机允许时可继续 |
| 磁盘不足、内存持续压力、数据库不可用 | 安全断点暂停相关工作并提示原因 | 暂停受影响的宿主任务，不继续制造数据 |
| Service 入库失败 | 保留采集结果，只重试入库 | 资源有余量且积压可控时，其他采集任务可继续 |

“不影响后面”指教材内容问题局部隔离，不承诺来源或服务器整体故障时仍不停请求。429 的 `Retry-After` 如存在应纳入最早重试时间，仍需结合其他预算；参见 [RFC 6585](https://datatracker.ietf.org/doc/html/rfc6585#section-4)。

人工处理页提供：查看原始证据、重试失败项、跳过本轮、暂停该教材、确认来源暂无题。任何跳过都保留原因，不静默把失败改成完整成功。需要人工操作的任务释放执行槽位，问题单长期保留。

## 7. 正常数据怎样入库

本阶段仍需把采集结果变成正式题库；“教案后置”不等于只存 Collector 而不建立可用题库。

- 采集过程中按页保存；单本任务结束或在安全点封存后，由后台自动校验并分批入库。
- 合格的新题/正常更新自动处理，普通批次不要求逐题审核。身份、教材范围、解析器整体异常先阻止受影响范围；局部坏题隔离。
- `snapshotComplete=false` 不再一律代表本次所有题目不可用：经过稳定封存、身份/范围确认和逐题质量检查后，可以将合格部分按“部分增量”处理。必须独立实现这类契约，不能给旧快照强行设置 complete=true，也不能复用完整快照的删除/替换逻辑。
- 一道题的内容、必要素材、标签及其相关目录关系在本次批次中一致提交，未通过检查的内容不用于覆盖旧题。
- 同源 ID 去重，批次可重复执行；缺席不是删除信号。保护人工禁用、人工题目、已有答案及跨教材共用的关系。
- 首次覆盖时允许合格批次逐步建立题库，任务显示新增/更新/不变/失败/待处理各多少；部分结果不能称为完整快照应用。
- 队列统一记录采集、检查、入库三阶段；采集完成但入库失败时，无需重新请求来源。

完整的题库版本发布系统不是本阶段前置要求。原有全量 apply 的长事务、禁用旧目录及重新启用题目的行为不能直接用作自动批次入口，必须先完成保守增量与结果状态改造。

## 8. 教材覆盖、每轮结果与用户确认的补采方式

台账同时记录三个事实，避免一个绿色状态掩盖问题：

| 指标 | 含义 |
| --- | --- |
| 采集覆盖 | 未开始、扫描中、范围完成、有缺页/来源限制 |
| 正式可用题量 | 通过检查并入库的题目数量与目录分布 |
| 未解决问题 | 失败页/素材/目录异常数量及人工结论 |

用户示例：第一轮来源显示 40,000，本次抓到 30,000；下一轮来源变成 41,000，本次可能抓到 39,000。系统应保存并使用每轮的合格内容，按稳定题目 ID 合并累计结果，不要求任一轮必须达到页面总数才允许入库。

页面必须区分：

- 来源标称题数及获取时间、目录/筛选口径；无法确认口径时明确标注。
- 本次抓取去重题数、本次合格题数、本次新增/更新题数。
- 累计正式可用题数，以及累计归属到各目录的关系。
- 已知失败页与尚未扫描范围、来源限制、仍缺必要素材的题目。

第二轮抓到 39,000 不等于累计只有 39,000；也不能把两轮 30,000 + 39,000 相加为 69,000。累计按来源题目 ID 的并集计算。旧题默认保留，因此累计数量甚至可能大于当前来源显示数；仅靠总数相等也不能证明内容完全覆盖。父子目录题数不能直接相加，同一题可属于多个目录。

单次未足量可能来自中断/失败，也可能来自来源总数变化、重复题、分页上限或统计口径。只有有具体证据时才标记“卡在某页”；否则标明“数量待核对/覆盖未确认”，不制造虚假的缺失清单。

第一阶段以一份明确的教材清单为验收基线：所有纳入且来源有题的教材至少建立一批通过质量检查的正式题目与目录关系，足以作为后续备课的题库基础；少量覆盖和目录缺口继续显著展示，不称为完整。来源无题或长期不可访问须人工确认并单列，不能自动移出分母伪造 100%。用户可决定这些明确例外是否影响进入教案阶段。

最新教材清单持续增长不应让里程碑永远无法验收：完成本轮基线后，新发现教材进入下一轮覆盖；这不等于忽略新教材。教案生成在题库阶段验收后再推进。

## 9. 第一阶段界面

同步中心采用四个子菜单：

1. **同步总览**：各学科发现总数、本轮目标、有题、待补齐、待处理及待入库情况；当前任务、下一本、公共暂停原因与资源摘要。
2. **教材发现**：按学段和学科刷新来源版本/教材清单，展示新增、改名、本次未发现及发现历史；与教材管理共用稳定身份。
3. **自动同步计划**：启停、范围、优先级、预算和周期；常用操作提供保守默认，细节放高级设置。
4. **同步任务**：内部包含“全部任务”和“待处理问题”标签；单本详情展示目录/页进度、日志、异常位置、入库结果与各次尝试。异常不另设侧边菜单。

教材资料与覆盖信息仍由题库管理中的教材管理承载，不在同步中心另建可编辑教材台账。普通待补齐、自动重试和人工待处理分别展示。

不再让用户反复手动选择 151 本创建大任务。课型、教案模板、复杂排版等暂不增加需求。

## 10. 实现边界与现有代码的差距

- 已有 Collector 持久任务、页断点、封存快照、来源错误分类、有限重试和单活动任务互斥，可复用。
- 当前 `QuestionTaskCreateModel.textbook_ids` 允许 1～200 本，前后端需一起改为单本语义。历史多本任务保留只读与原始范围，不能强行解释为单本。
- 当前完整快照 apply 要求任务成功和完整封存，无法直接支持用户确认的“30,000/40,000 也要保留可用题”。需要新增受控的部分增量校验/入库语义，区分已结束并封存的不完整快照和仍在变化的运行数据；首次库非空之后的持续合并必须单独测试。
- 现有 Service/Collector 的 `active_slot` 控制一个活动任务，不能直接创建 151 个都占 active_slot 的 queued 任务。新待办队列与实际执行槽位分开，派发时才占槽位。
- 现有多本任务终止时会取消尚未执行 scope；改成独立单本任务后，不通过父任务失败级联取消后续书。
- 项目已有 APScheduler 和主节点协调，不必再引入一套复杂队列平台。周期触发只做扫描到期项和派发；任务、冷却时间、游标与重试结果持久化在业务表。
- 必须有派发幂等键、任务租约/所有者与重启核对：先确认远端是否仍在运行，再接管或续采，不能只凭本地进程消失另开相同采集。
- 调度错过多个触发点时合并一次检查，不能重启后补发大量教材任务；并发限制与合并能力见 [APScheduler 3 文档](https://apscheduler.readthedocs.io/en/3.x/userguide.html#missed-job-executions-and-coalescing)，业务数据库的唯一约束仍需独立保证。
- Collector 当前只保留最近 500 个终态 job；长期运行需要先保存业务任务摘要和未处理异常，再按保留策略清理，不能依赖旧 job 永远可查。
- 标准化学科范围需要贯穿元数据同步状态、正式教材、采集 run、缓存和唯一键；当前按 provider 维护的元数据状态不足以隔离未来多学科。

建议新增或扩展的持久信息限于计划、教材调度状态、单本任务/尝试、异常记录、来源冷却；优先复用当前 job、scope 与批次结果，避免重复建设两套状态机。

## 11. 容量与保留策略是自动运行的前置条件

- 当前剩余约 16 GiB，不能在没有估算和停止阈值的情况下启动全部教材连续采集。
- 记录新增唯一素材字节、数据库/索引增长、原始响应、快照、Service 暂存和备份各自占用。素材按内容摘要复用；教材重叠不会等比例增加文件，但关系与历史仍会增长。
- 已验收素材与必要原始证据继续保留；中间文件、重复历史快照与过期日志制定保留窗口，保留未解决异常和恢复所需数据。任何生产清理单独验证恢复，不在本次需求梳理中删除。
- 一批代表教材完成后给出覆盖全部的容量区间，结合真实跨教材去重率判断扩盘或迁移素材存储；不能把一个教材样本简单乘以 151 当作保证。
- 备份验证、磁盘低水位暂停、日志轮转和失败告警应先于无人值守长跑。

## 12. 实施顺序与验收

| 阶段 | 交付 | 关键验收 |
| --- | --- | --- |
| A. 任务和台账 | 单本任务、数学教材发现与覆盖状态、未来学科标识边界 | 新增/改名/暂时缺席正确处理；一个任务只能一本；历史任务不丢 |
| B. 后台自动运行 | 待办队列、持久调度、重试/冷却、异常列表 | 一本异常后下一本可执行；重启不重复抓；待人工任务不占执行位 |
| C. 正式入库与容量保护 | 自动检查、批次写入恢复、人工保护、保留策略与资源门槛 | 采集成功入库失败只重试入库；重复不重复加题；坏题不覆盖好题；空间不足可恢复暂停 |
| D. 小规模实测 | 代表教材运行指标与来源反馈、预算校准 | 量化每本耗时和增长；模拟 429/验证/磁盘压力验证暂停；不通过真实加压诱发风控 |
| E. 全部教材基础覆盖与循环补齐 | 新版优先兼顾旧版，动态发现新增，每本先有可用题，随后循环补采更新 | 30,000/40,000 可形成有缺口的可用题库；下一轮 39,000/41,000 去重合并；不覆盖人工禁用，不丢此前题目；不同教材均能获得执行机会 |
| F. 后续扩展 | 其他学科适配；题库阶段验收后恢复教案规划 | 多学科不串数据/不突破同源预算；教案需求单独确认 |

A～C 完成后才能启动 D 的受控实测与 E 的无人值守运行。本次没有开启计划，所列周期、预算和指标都是待实施方案。

## 13. 仍需确定的参数

- 第一阶段采用用户已确认的“每本先有一批可用题，循环补齐”。题量/目录覆盖展示方式按本文件第 8 节实施；何时认为基础题库适合进入教案阶段，由实际覆盖台账验收。
- 每日请求/时长/存储预算、低水位阈值、冷却和最大重试次数：根据代表教材实测给出配置，不先承诺每日几本。
- 资源不足时的扩容或素材存储方案：先完成容量估算再决定。
- 第一阶段异常提醒集中在同步任务的“待处理问题”标签；公共暂停原因在总览统一显示。若需要邮件等外部通知，另行明确渠道与授权。

此前《题库入库需求梳理》关于自动检查、人工只处理异常、保护人工决定的原则继续有效；其教案使用侧优先级以本文件的“先题库覆盖、后教案”顺序为准。
