## 1. 当前入口与边界

- collector/server.cjs：独立 HTTP 服务与固定任务编排（实现在 src/api/）。
- zujuan_metadata_sync.cjs：版本、教材元数据发现（实现在 src/jobs/metadata_run.cjs、src/cli/）。
- zujuan_question_sync.cjs：当前 HTTP 内容任务使用的题目列表 API 入口（实现在 src/jobs/question_run.cjs、src/cli/）。

- 仅写本工程 SQLite、raw gzip、素材和运行快照，不写正式 MySQL。
- 当前列表入口答案/解析标记 not_collected；它们不是本阶段基础题干采集的必采成功条件。

## 3. 从旧扫描方案迁入的有效要求

以下是后续实现与验收要求。上表表示当前状态，不能因为本节写了要求就视为全部完成。

### 3.1 分页、总数和完成

- 每个目录分别维护 sourceReportedTotal/latestSourceTotal、maxObservedTotal、targetPages、实际页容量。
- total 用于展示及动态范围估算，不要求最终唯一题数与其相等，也不要求每页返回相同 total。
- total 增加时扩展范围；减少时不缩小已确定范围；到目标后执行有限边界探测。
- total 缺失时依靠确认空页和有限零增量窗口判断边界；安全上限只防止无限请求，触发必须记异常。
- 一个目录发生 1001 页重复不能推断全站固定 1000 页；不能把到达固定上限视为完整采集成功。
- 非空 HTML 解析出零题不等于真正空页；目标范围内空页但后页有题时，记录异常并继续处理。
- 页内、跨页题号重复进行幂等去重；同题跨知识点保留关系。重复响应签名用于诊断分页卡死。

### 3.2 并发结算与断点

- 一批请求逐页独立结算，不能因为中间失败而丢掉后面已成功的结果。
- 停止派发新请求后，尽可能保存已返回的成功页；未完成请求留为待恢复。
- 页数据和成功标记同事务提交，重试不得重复增加已尝试页数或题目/关系数。
- 区分 highestAttemptedPage、lastContiguousSuccessfulPage、attemptedPageNumbers、unresolvedPageNumbers。
- 不能只保存“最高成功页”；恢复应识别中间缺页，并继承已封存运行到新运行。
- 保存范围指纹及解析器版本；长时间间隔后的来源分页位移需要重扫边界、去重或重扫受影响目录，不能承诺页码断点使上游静止。

### 3.3 异常影响范围

| 层级 | 例子 | 目标行为 |
| --- | --- | --- |
| 单素材/题卡 | 404、超限、局部字段或稳定 ID 缺失 | 保存可用题目与原始证据，隔离无效对象，记录待修复项 |
| 单页 | 超时耗尽、非法响应、重复页、异常空页 | 保存页结果和原因，其他有效页继续 |
| 单知识点 | 连续窗口无新增、参数无效、分页卡死、安全上限 | 有限复查后记录该节点问题，继续其他节点 |
| 来源/会话 | 真正滑块、持续限流、多个独立目录同类失败 | 停止该来源新请求，保存断点，冷却或等待手动恢复 |
| 全局存储/执行环境 | SQLite/事务写入失败、磁盘满、浏览器不可用 | 停止本次执行，不能假装成功 |
| 用户取消 | 明确停止请求 | 保存可保存的数据并结束，不自动重启 |

域名、协议、大小和路径限制继续作用于相应请求。原始快照写入失败须记录，磁盘/存储系统性失败不能降级成普通页警告。不能自动丢弃有实际内容的缺图，也不能把不完整数据用于删除正式旧数据。

### 3.4 扫描与数据质量

~~~text
scanComplete      是否完成已确定范围的一轮处理
dataComplete      必采题目/关系/素材是否完整
completionQuality completed / completed_with_issues
snapshotComplete  是否满足完整快照应用条件
~~~

- 100% 表示扫描结束，不使用已采题数/来源总数判断最终成功。
- 一个页码完成有限尝试后得到成功/失败/重复/空页结果，可计入扫描进度；全局阻断时尚未真正处理的页面不能批量算作已完成。
- 当前终态可以是 completed 且 dataComplete=false；必须同时标记质量，不允许完整应用。
- 来源题数、每知识点 COUNT(DISTINCT question_external_id)、题卡 occurrenceCount 分开保留；不能用实际题数覆盖来源题数掩盖差异。

## 4. 无人值守目标（待实现）

采用“保存断点 → 结束执行 → 持久化冷却计划 → 到期探测 → 恢复或延长等待”，不默认把窗口置前等待人工操作。

- 暂时网络错误和 5xx：少量页内重试，耗尽后记页问题或判断是否全局故障。
- 429：优先遵守 Retry-After；同一来源的其他请求也要暂停。
- 真正保护页：保存原始证据、失败页、运行和原因，有限冷却后探测。
- 401/403 必须按响应证据分类，不能直接等同“未登录”；持续拒绝时停止自动重试，保留手动入口。
- 冷却间隔、最大恢复次数和预算可配置；15 分钟/1 小时/4 小时仅为讨论的初始建议，尚未配置或验证。
- Service 持有调度权，Collector 只执行一次任务；不再增加第二套独立自动调度。
- 手动恢复与自动恢复同一逻辑；取消任务后不自动启动。
- 恢复仍被拒绝时明确保留状态，不能保证公开接口一定在冷却后恢复。
- 已扫描但不完整的任务支持失败页、知识点、素材补采，不必重新下载整本。

## 6. 验收清单

1. 合法 JSON 的题干包含验证码/captcha/challenge 等词仍正常；真正保护响应被正确识别。
2. total 增大、减小、为 0、缺失，及跨页部分题号重复均不导致整本失败。
3. 重复页、目标范围内空页且后页有题、非空解析失败分别记录。
4. 8 路窗口第 N 页失败，后续成功页照常保存；续采可准确补 N。
5. 图片失败保留题干与 URL；空公式占位和真实缺图分别处理。
6. 单知识点卡死不阻止其他节点；全局存储故障会停止。
7. 100% 带异常不可完整应用；各统计来源可核对。
8. 进程终止、重启、旧全局断点大于当前运行断点时不漏页。
9. 自动/手动恢复竞争只执行一次，冷却计划重启不丢、取消后不执行。
10. 真实整册运行保存版本、参数、run、扫描覆盖、异常清单和素材核验结果。
