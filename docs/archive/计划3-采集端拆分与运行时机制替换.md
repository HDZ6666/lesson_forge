## 1. 背景与目标

2026-09-07 源码现状：

- 三个采集脚本 `zujuan_sync.cjs` 4,993 行、`zujuan_question_sync.cjs` 4,802 行、`zujuan_metadata_sync.cjs` 2,211 行；`lib/api_store.cjs` 3,131 行；`server.cjs` 1,537 行。顶层函数分别为 109 / 104 / 87 / 55 / 24 个。
- 新入口与旧入口有 24 个同名函数，与元数据脚本有 18 个同名函数：工具、文件锁、URL 白名单、HTML 小解析器、素材下载、题目归一化各自维护一份。
- 新入口 `require` 了旧入口（`validateResumeSourceRun`）和元数据脚本（`launchCollectorContext` 等），旧入口无法下线。
- `server.cjs` 的 job 只在内存；用正则解析子进程 stdout 中的 `run=N`、`questionsSeen:` 等文本取进度；没有 job 超时；互斥只在进程内。这对应实际问题台账的 COL-004（真实错误被帮助文字覆盖、最新 run 未回绑）、COL-009（已保存页面界面仍为 0）以及"collector 重启即丢任务"。

目标：

1. 边界架构与对外契约不变（第 2 节），把采集端按职责拆成可独立单测的模块。
2. 用结构化事件替代 stdout 正则解析；job 持久化到 SQLite；补 job 总超时与停滞检测；互斥跨进程。
3. 历史真实故障 COL-003 / COL-010 / COL-012 固化为解析器与策略层的回归测试。
4. 旧入口降级为 `legacy/`，脚本入口收口，文档同步。

本计划明确不做：

- 不换语言，不引入 Crawlee / Scrapy 等爬虫框架，不改为 ESM / TypeScript。
- 不新增 npm 运行时依赖（保持仅 `playwright-core`）。HTML 解析器替换为 `node-html-parser`、CLI 参数库替换为 `commander` 记为后续可选项。
- 不修改现有 SQLite 业务表、run 封存表与触发器；只新增 `collector_jobs` 表。
- 不修改 CLI 参数名与默认值；不修改 `/v1/*` 路由与现有响应字段（允许新增字段）。
- 不实现 service 侧自动恢复调度（见后端进度第 5 节），但为其提供重启后仍可查询的持久 job 状态。

### 阶段 3：执行器与运行时机制（唯一行为变更阶段）

3.1 `runSync`（约 3976–4706 行）拆为 `src/jobs/question_run.cjs` 的 `prepareRun`（锁、schema、scope、resume 校验、store 与浏览器初始化）、`probeTextbookTotal`、`crawlCatalog`（目录循环）、`settleWindow`（逐页结算）、`sealRun`（终态、封存、资源释放）；对外 `runSync(options, dependencies)` 签名不变。`runDiscovery` 迁到 `src/jobs/metadata_run.cjs`。

3.2 结构化事件 `src/jobs/events.cjs`：

- 通道：server 以 `stdio: ['ignore', 'pipe', 'pipe', 'ipc']` 启动子进程，子进程通过 `process.send(event)` 发送；CLI 直跑无 IPC 时默认不输出，传 `--events-stdout` 时以 `@@event ` 前缀的 NDJSON 行写 stdout 供调试。
- 事件类型：`run_created{runType,runId,textbookExternalId}`、`progress{runId,catalogCount,pagesOk,questionsSeen,uniqueQuestionCount,sourceTotal,percent}`、`heartbeat{runId,at,stage}`、`verification_wait{runId,reason}`、`error{code,message,runId,recoverable,failedPages}`、`sealed{runId,status,snapshotComplete,scanComplete,dataComplete,completionQuality,counts}`、`metadata_run_created{runId}`、`metadata_summary{versionCount,textbookCount}`。
- server 删除 `record()` 中的全部正则；`lines` 只用于 logTail。`lastError()` 只在没有收到 `error` 事件时兜底。`error.code` 落到 job 与 scope 的新增字段 `errorCode`。

3.3 `src/api/job_store.cjs`：新表 `collector_jobs`（`id run_type status phase active_slot payload_json scope_json metadata_run_id collector_run_id progress_percent error_code error_message current_textbook_id created_at started_at finished_at heartbeat_at child_pid cancel_requested log_tail`，`active_slot` 唯一索引）。`CollectorJobManager` 创建 job 即写行（`active_slot='1'`，唯一约束冲突返回 409，实现跨进程互斥）；状态变化写回；终态置 `active_slot=NULL`；构造时加载最近 100 条，前一进程遗留的活动 job 标为 `interrupted`（scope 存在可续采 run）或 `failed`（`error_code=collector_restarted`），并调用 `sealOrphan*Run`。`GET /v1/jobs/:id` 对重启后的历史 job 返回持久状态而不是 404。

3.4 超时与停滞：`COLLECTOR_JOB_TIMEOUT_MS`（默认 24 小时）、`COLLECTOR_STALL_TIMEOUT_MS`（默认 20 分钟；`heartbeat`、`progress`、`verification_wait` 事件都刷新）。触发后走 `cancel` 路径（SIGTERM，12 秒后 SIGKILL），终态为 `interrupted`（可续采）或 `failed`，`error_code` 为 `job_timeout` 或 `stalled`。

3.5 `server.cjs` 瘦身：路由到 `src/api/routes.cjs`；`sendJson sendAssetResponse readJson safeEqual` 到 `src/api/http.cjs`；`publicJob aggregateLiveProgress` 到 `src/api/progress.cjs`；`CollectorJobManager` 到 `src/api/job_manager.cjs`；`server.cjs` 只保留 `main()` 与 re-export。

验收：

- A3-1 C1–C8（C3 中 `publicJob` 字段集合为原集合加 `errorCode`）。
- A3-2 `rg "match\(/(metadata-run|发现|textbooksSeen|本次同步|questionsSeen|run=)" src server.cjs` 无匹配。
- A3-3 集成测试使用假子进程脚本，不启动 Chrome：子进程发出 `run_created` 后 `GET /v1/jobs/:id` 立即读到 `collectorRunId`；子进程发出 `error{code:'verification_required',recoverable:true}` 后以非 0 退出，job 为 `blocked`，`errorCode` 正确，`errorMessage` 不是"使用 --help 查看参数"（COL-004 回归）。
- A3-4 两个 `CollectorJobManager` 实例共用同一 SQLite：第二个 `start()` 得到 409；第一个到终态后第二个可以启动。
- A3-5 重启恢复：管理器 A 启动 job 且子进程停滞，销毁 A 后用同一库新建 B，该 job 为 `interrupted` 或 `failed`，`errorCode=collector_restarted`，对应 run 的 `snapshot_locked_at` 非空。
- A3-6 停滞：`COLLECTOR_STALL_TIMEOUT_MS=200` 下子进程不发心跳，job 终态 `errorCode=stalled` 且子进程被终止；持续发出 `verification_wait` 时不判停滞。
- A3-7 `node zujuan_question_sync.cjs --help` 输出不变；只有 `--events-stdout` 才输出 `@@event` 行。
- A3-8 service 侧 `pytest service/tests/plugins/bank/test_collector_client.py test_collector_remote_contract.py test_question_collector_contract.py test_sync_run_service.py` 通过，service 代码不改。
