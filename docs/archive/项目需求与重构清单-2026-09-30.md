# 项目需求与重构清单

> 已于 2026-10-01 归档。以下为历史原文，文中的“当前”“唯一入口”“下一步”和完成状态只指当时，不用于指挥本轮实施。接手请读[文档入口](../README.md)；当前需求以[重构实施规格](../重构实施规格.md)为准，进度以[实施任务清单](../实施任务清单.md)为准。

创建日期：2026-09-30。更新时间：2026-10-01。

本文汇总本轮确认的业务需求、功能归属和需要重构的代码范围，作为后续实施的主要需求入口。当前目标是建立自动运行、逐本采集、允许部分成果入库并持续补齐的题库系统；每本教材形成基础可用题库后，再推进教案生成。

本文是需求与实施清单，不代表功能已经实现。菜单、任务状态和代码拆分属于目标设计；本轮只新增文档及维护文档索引，没有创建 worktree、执行数据库迁移或开启自动采集。

## 1 已确认的需求

| 编号 | 需求 | 明确边界 |
| --- | --- | --- |
| R01 | 主要供自己或少量教师备课 | 正常数据自动检查后入库，人工重点处理异常，不逐题审批几万道题 |
| R02 | 采集在服务器后台自动运行 | 关闭页面不影响；服务器或进程重启后可核对并恢复任务 |
| R03 | 支持同步一个学科的全部教材 | 通过自动计划持续派发单本任务，不创建包含全部教材的大内容任务 |
| R04 | 每个内容同步任务只对应一本教材 | 手动与自动任务执行相同规则；历史多本任务保留原记录 |
| R05 | 首次覆盖全部，随后循环补齐与定期更新 | 新旧版都保留，新版优先，但不能使旧版长期得不到执行机会 |
| R06 | 教材数量动态变化 | 定期发现新增、改名及本次未发现的教材；不把 151 等数量写死 |
| R07 | 稳定优先，全天低负载 | 依据服务器资源、来源反馈和工作预算决定是否执行，不承诺固定每天几本 |
| R08 | 单次没抓全也保留可用成果 | 合格题目自动分批入库；显示缺口，支持重跑和下一轮补齐 |
| R09 | 单本或局部异常不拖住其他教材 | 来源级访问阻断、磁盘不足等公共故障仍要暂停相关工作 |
| R10 | 保留五个题库页面，新增学科管理 | 版本管理、教材管理、目录管理、题目管理、教材浏览全部保留 |
| R11 | 同步中心作为独立一级模块 | 四个子菜单；异常收进同步任务，不另设异常处理侧边菜单 |
| R12 | 最后保留一个教案生成模块 | 现有代码和数据保留，教案编辑重构安排在题库基础覆盖验收后 |
| R13 | 保持当前项目结构，隔离重构 | 保留 `pc / service / collector` 三端；后续在独立 worktree 和测试环境实施 |
| R14 | 教师按自己确定的内容筛选与组织题目 | 教案页面和 Word 只展示题干及必要素材，不展示答案、解析或教学引导；不删除题库原有答案 |
| R15 | 支持先列内容配题和直接从题库选题 | 两种入口共用草稿；同一内容支持多组条件，例如基础填空 2 题＋提升解答 1 题；每题只占一个规则名额 |
| R16 | 网页编辑后保存和导出 Word | 补齐、换题与调整条件保留已有人工结果；严格筛选不自动放宽；导出使用同一保存版本和题目顺序 |

尚未确定的具体运行参数集中列在第 11 节；不能将建议值当作已批准并正在执行的配置。

## 2 最终功能结构

```text
题库管理
├─ 学科管理
├─ 版本管理
├─ 教材管理
├─ 目录管理
├─ 题目管理
└─ 教材浏览

同步中心
├─ 同步总览
├─ 教材发现
├─ 自动同步计划
└─ 同步任务
   ├─ 全部任务
   └─ 待处理问题

教案生成
└─ 一个主页面，包含筛选组题、内容编辑、预览换题、草稿历史和 Word 导出
```

“全部任务”和“待处理问题”是同步任务页面内部的标签，不新增侧边菜单。账号、权限等通用系统功能继续沿用现有底座，本次只调整业务模块。

### 2.1 题库管理

| 页面 | 处理方式 | 功能与调整 |
| --- | --- | --- |
| 学科管理 | 新增 | 维护学科及适用学段、启用状态、来源映射；第一阶段接入数学，其他学科逐个验证解析能力 |
| 版本管理 | 保留并扩展 | 保留来源与人工版本、新旧版标识；增加学段/学科筛选，避免不同学科同名版本混淆 |
| 教材管理 | 保留并扩展 | 维护唯一教材资料；展示累计可用题量、目录覆盖、最近同步、未解决问题及下次安排；“立即同步”进入统一队列 |
| 目录管理 | 保留并适配 | 维护章、节、知识点及层级；保留稳定 ID，明确来源与人工维护边界 |
| 题目管理 | 保留并完善 | 查询内容与素材、维护人工题目、启停来源题目；展示来源和变化记录；同步不得撤销人工禁用 |
| 教材浏览 | 保留并完善 | 通过学段、学科、版本、教材和目录浏览正式可用题目；用于检查采集效果和日常查题 |

业务启停与自动同步启停分开：暂停采集不删除或隐藏已有题目；人工禁用题目影响抽题资格，下一轮同步不能自动重新启用。具体展示沿用现有权限边界。

### 2.2 同步中心

| 子模块 | 主要职责 | 不承担的职责 |
| --- | --- | --- |
| 同步总览 | 学科教材数、本轮目标、有题/待补齐/待处理情况、当前任务、下一本、公共暂停原因、资源和存储摘要 | 不维护另一份教材资料，不重复提供一套执行器 |
| 教材发现 | 刷新来源的版本/教材清单，展示新增、改名、本次未发现和发现历史 | 不要求正常新增项逐个审批，不直接采集全部题目 |
| 自动同步计划 | 学科范围、循环策略、新版优先、运行预算、启停和单本调度覆盖项 | 不将全部教材塞入一个内容任务，不绕过来源冷却 |
| 同步任务 | 一本教材一次运行的进度、结果、日志、补采和重跑；集中查看待处理问题 | 不再拆出独立入库中心、日志中心或强制审核中心 |

教材发现与教材管理使用同一教材身份。发现过程记录来源观察结果；通过身份校验的正常新增项自动登记。归属冲突或疑似错误单独处理。一次教材发现可以覆盖一个学科，属于元数据操作；“一本教材”约束针对内容同步任务。

自动计划覆盖整个学科，单本手动操作只是同一计划/队列体系中的一次请求。调度列表、教材页的同步信息和总览从相同状态读取，避免三处维护不同事实。

### 2.3 教案生成

保留现有抽题、预览、换题、历史记录和 Word 导出基础，统一在一个模块内。老师自行确定教学内容，按条件筛选与组织题目，网页编辑后导出；同时支持先列内容配题和直接从题库选题。两种入口共用草稿，同一内容可以配置多组题型、难度和数量条件。教案端不展示答案、解析或教师引导，编辑重点是内容分组、选题条件与题目顺序。

筛选必须区分符合条件总数和排除已选题后的可选数；同题不重复占多个规则名额，数量不足不自动放宽。补齐只填缺额，改条件或降低目标不自动删除原题；手选题可以进入待整理，移动和排序只修改教案。

实现继续使用现有 `lesson` 插件：新增有版本的草稿结构、候选分页、严格多规则配题和编辑接口，保留旧记录与快照，补齐素材保留及 Word 一致性。第一版按一本教材内跨章节选题设计；复杂材料导入、题干编辑和跨教材组题后续明确，不依赖 AI 才能完成选题。

详见[教案生成需求与交互梳理](教案生成需求与交互梳理-2026-09-30.md)及[教案选题与编辑实现方案](教案选题与编辑实现方案-2026-10-01.md)。当前完成的是需求、独立原型和实现方案，L01～L08 业务改造全部待实施，仍安排在题库基础覆盖验收后；已有实现与历史数据继续保留。

## 3 业务流程与单本任务

```text
发现并登记教材
    ↓
自动计划挑选到期或未覆盖教材
    ↓
创建一本教材的内容任务
    ↓
采集并保存页级进度
    ↓
结束或安全封存本次采集结果
    ↓
自动检查，分离合格内容与问题项
    ↓
后台分批入库，记录各批次结果
    ↓
展示本轮结果，登记后续补采或刷新时间
    ↓
调度下一本可执行教材
```

一本任务包含采集、检查、入库阶段。采集失败但有合格成果，仍可进入受控的部分增量入库；采集成功而入库失败，只重试入库，不重复请求来源。

短时恢复属于未结束任务的一次新执行尝试。已结束任务点击“重跑/补采”，创建关联原任务的新单本任务，保留旧结果；下一轮周期更新也创建新任务。新任务可复用素材和可信断点，不等于从头下载一切。

### 3.1 操作定义

| 操作 | 行为 |
| --- | --- |
| 立即同步 | 进入统一队列；若同教材已有任务，定位已有任务或调整优先级，不重复启动 |
| 暂停自动计划 | 停止该计划继续派发，当前任务默认正常收尾；界面明确说明影响 |
| 暂停教材自动同步 | 停止该教材后续自动派发，保留题库；当前任务是否停止通过独立操作表达 |
| 停止当前任务 | 在安全边界停止后续工作，保留已采集及已提交结果；进行中的事务明确完成或回滚，不假装整轮撤销 |
| 补采 | 优先处理已知失败与未覆盖范围，核对断点有效性后执行 |
| 重新同步 | 重新扫描当前来源内容，按来源 ID 合并，不清空已有题目 |
| 重试入库 | 使用已保存且可验证的采集结果重试数据库处理 |
| 跳过本轮问题 | 记录原因与后续安排，不标记问题已解决，也不宣称整本完整 |

手动操作仍遵守资源与来源限制。公共紧急暂停与“暂停计划”分开：前者可要求当前相关任务在安全点停止。

### 3.2 状态与数量口径

必须分别保存和展示运行阶段、入库结果、覆盖情况。最终数据库枚举在实现时细化，不继续用一个 `completed` 同时表示采集结束、全部入库和来源全量覆盖。

示例显示：“本轮已结束；已入库 30,000 道；仍有未覆盖范围；已安排下次同步。”

任务详情展示来源标称数及观察时间、本次去重题数、本次合格数、新增/更新/不变数、入库失败数和已知缺口。教材页展示累计正式可用题数及目录分布，累计数与本次数不能混用。

用户示例中的第一轮 30,000/40,000、第二轮 39,000/41,000 都允许形成可用结果。累计按稳定来源 ID 合并，不能直接相加，也不能用第二轮数量覆盖累计数量。父子目录可包含同一道题；来源标称数口径或时间不同，不能仅凭差值断言具体漏了多少题。

## 4 自动运行与数据规则

### 4.1 动态教材清单与基础覆盖

定期按来源、学段和学科刷新清单。新增教材进入首次覆盖待办；改名不创建重复教材；单次未发现只记录观察，不删除旧题。教材被人工暂停或排除后，后续发现不能擅自恢复调度。

每轮保留目标清单与目标数，同时展示最新总数。新教材进入后续待办，不使本轮验收目标无解释地变化。第一阶段优先让所有纳入教材都有一批通过检查的可用题，再持续提高覆盖；不能只围着第一本反复补采。

“有可用题”“有较多目录覆盖”“完成范围扫描”是不同指标。来源无题或长期不可访问的教材人工确认后单列，不静默从分母剔除。是否达到进入教案阶段的条件依据教材台账验收，不强求任一轮抓到来源标称的全部题目。

### 4.2 调度与来源反馈

初期同一时间只采一本，采用固定规则及明确上限。未覆盖教材、新版、等待较久的旧版和到期补采都需要获得机会；重试有预算，避免坏任务无限占用。

每次派发检查：计划启用、教材到期、同教材无重复活动任务、来源无冷却、资源有余量、当日预算未耗尽、待入库积压可控。待办队列不占执行槽位，派发时再获取执行权。

记录请求量、延迟、429/验证事件、成功页和重试页、下载量、耗时、内存峰值及磁盘增长。运行异常降速或暂停，稳定后才在配置上限内恢复；不通过故意触发来源阻断来寻找速度极限。

每天最大启动本数可作为保护上限，但不是必须完成的产量。同一本可以跨天恢复。未来不同学科使用同一站点时，共享来源限制；不能通过换学科或换教材绕开冷却。

### 4.3 增量入库与部分结果

采集数据按页持久保存。稳定封存的不完整快照在通过身份、范围和逐题质量检查后，可以导入合格部分；仍在变化的数据不能假装成稳定快照。

正式写入使用有界批次和短事务；一道题本次涉及的内容、目录关系、标签与素材引用一致提交。素材先检查，再让题目进入可用集合。批次进度与结果可靠记录，重复执行不会重复加题。

新增题目插入，正常变化更新，未变化跳过。未抓到不等于删除；空答案不覆盖已有可信答案；坏题不覆盖好题；人工禁用及人工题目得到保护。共享题目、标签和素材的处理保留其他教材仍使用的关联。

允许合格批次逐步可用。中途失败保留已提交部分，明确显示部分结果；不承诺整本事务回滚或原子发布。不得将部分增量结果记为旧模型中的完整快照已应用。

### 4.4 补采与定期刷新

已知缺口、自动重试和正常周期刷新分别安排。未补齐的教材不必等待充分覆盖教材的常规刷新周期；但首次覆盖其他教材也不能被无限补采挤占。

按最新排序的来源会因新题插入发生分页变化，旧页码不保证安全。跨轮补采核对教材/过滤条件/排序、检查新内容并对断点附近有界重叠扫描；无法验证断点时重新扫描相应范围。

增量入库不等于来源只需要增量请求。没有可靠变更游标时，保留周期性范围核对；不能凭第一页不变判断整本未变化。

## 5 异常归属与处理

异常展示归入同步任务，但底层须结构化持久保存，不能只依赖日志尾部或任务的最后一条错误。问题至少能定位来源、教材、任务、目录/页/题/素材、错误类别、证据、尝试次数、下次处理时间和处理结果。

| 分类 | 展示与动作 | 队列影响 |
| --- | --- | --- |
| 正常待补齐 | 如达到本次预算或尚有未扫描范围，登记下一轮 | 继续其他教材，不要求人工确认 |
| 系统重试中 | 临时网络或下载失败，显示重试次数和下次时间 | 有限重试，长等待释放执行位置 |
| 需要人工处理 | 目录无法识别、身份冲突、需要验证等，进入“待处理问题”标签 | 教材局部问题不阻塞其他可执行教材 |
| 来源公共问题 | 频率限制、验证码或来源级访问阻断，显示统一原因 | 暂停同来源，冷却/解除后再调度 |
| 主机公共问题 | 磁盘不足、持续内存压力、数据库不可用 | 暂停受影响工作并保存恢复位置 |

待处理问题支持按教材、错误类型和时间筛选，并能回到任务上下文。问题在任务归档后仍可查；后续任务确实修复对应资源或范围时才自动关闭，记录解决任务和证据。不能因为新任务成功就关闭旧任务全部问题。

来源或主机公共问题保存一份原因与恢复状态，任务引用该原因，不为每本教材生成重复问题。正常补采、自动重试和人工待处理分别统计，避免把所有未抓全任务都列成需要人处理。

## 6 功能保留与入口迁移

| 当前功能 | 处理分类 | 后续位置与边界 |
| --- | --- | --- |
| 五个题库页面 | 保留并适配 | 仍在题库管理，统一学科筛选与来源身份 |
| 学科管理 | 新增 | 题库管理首个子菜单 |
| 现有同步中心 | 重构整合 | 职责拆入同步总览、教材发现、自动计划、同步任务 |
| 同步教材 | 迁移整合 | 来源元数据与发现历史进入教材发现，调度进入自动计划 |
| 同步题库 | 重构 | 新入口一本教材；旧多本记录和范围保持可读 |

## 8 数据与接口设计约束

实现时优先复用现有 job、scope、run 和持久化能力。需要补齐的概念是学科/来源范围、计划、教材调度状态、执行尝试、入库批次、问题记录和公共冷却；是否新增表由迁移设计决定，不预设所有概念都建一张表。

- 来源身份必须稳定且覆盖学科命名空间；教材不能仅按名称匹配，题目不能以内容相似替代来源 ID 去重。
- 同一道来源题可属于多个教材/目录，题目实体和教材关系分别处理，避免删除其他教材的关系。
- 前端只提交服务器认可的教材与来源配置，学科管理不能变成任意脚本、URL 或数据库路径执行入口。
- 采集结果与入库批次均绑定确定的来源、范围和摘要；不一致时停止相关批次，不能忽略异常继续覆盖。
- 派发和提交幂等，避免请求超时后的重试重复执行；跨进程的唯一约束不能仅靠内存变量实现。
- 历史兼容与新流程标识明确，旧的完整快照回退语义不得错误用于新部分增量任务。
- 教案候选列表、计数和配题共用严格条件；教案条目绑定稳定来源题身份及选入快照，同题不能因多个目录关系重复计数。
- 教案修改采用版本校验和请求去重；内容、规则与条目归属一致提交。Word 读取已保存版本，不能混用保存前后内容。
- 新教案页面及接口采用题干白名单，不返回答案、解析和旧教学文字；快照素材参与有效引用保护，不受普通题库清理误删。

## 10 业务验收清单

以下为实施后的验收项，本次均未标记完成。

- [ ] 保留五个题库页面及已有数据；新增学科后不同学科同名版本不会串数据。
- [ ] 新任务只能一本教材；旧多本任务仍能查看真实历史范围。
- [ ] 自动发现新增教材只登记一次；改名不重复；暂时未发现不删除旧题。
- [ ] 自动计划可以覆盖全部教材，但同一时间只执行预算允许的单本任务；手动请求不会重复启动。
- [ ] 第一轮 30,000/40,000 的合格内容可以入库；第二轮 39,000/41,000 按来源 ID 合并，保留此前内容且计数正确。
- [ ] 个别坏题被隔离，其他合格题可入库；来源/范围不匹配或整体数据契约破坏时，受影响批次不写入。
- [ ] 人工禁用不被下一轮撤销；人工题目、已有答案和其他教材关系不被误覆盖或删除。
- [ ] 抓取结束但入库失败时，仅重试入库；批次提交后进程崩溃，恢复不会重复数据或错误计数。
- [ ] 一本教材解析失败后，其他可执行教材继续；正常待补齐不要求人工点击才能推进。
- [ ] 模拟来源限速/验证时同来源队列暂停，重启后冷却仍有效；不能通过换教材绕开限制。
- [ ] 来源插入新题导致分页移动时，恢复能识别风险并避免盲目沿用旧游标；缺口状态真实。
- [ ] 关闭页面任务继续；重启先核对远端运行状态，再接管或恢复，不产生双重采集。
- [ ] 待处理问题在旧任务归档后仍可查；新任务只关闭确实解决的问题，跳过不等于解决。
- [ ] 暂停计划、停止当前任务、补采、重跑、重试入库各自符合第 3 节定义。
- [ ] 来源标称、本次、累计数量清楚分开；“本轮结束”不被展示成全部内容已完整覆盖。
- [ ] 磁盘/内存压力或待入库积压超限时安全暂停；恢复后继续，已有素材和记录不丢失。
- [ ] 新版优先且旧版不饥饿；多次失败任务有有限重试预算，不持续挤占其他教材。
- [ ] 备份可恢复，日志/快照保留可解释；未解决问题和仍被使用的素材不会被清理掉。
- [ ] 两种教案入口共用草稿；同一内容可以按多组条件配题，同题只占一个规则名额，缺额可解释。
- [ ] 教案筛选数量和候选一致；条件不足不放宽，补齐、换题及改条件不覆盖人工选择和顺序。
- [ ] 手选、分组、排序、移出、撤销和保存可用；超时重试或双窗口编辑不会重复选入或覆盖新结果。
- [ ] 教案详情、预览和真实 Word 只展示题目及必要素材；待整理题不漏导，保存版本与导出内容一致。
- [ ] 旧教案与题目快照仍可读；权限及素材保留正确；真实课例和近 5 万题性能验收有证据。

## 11 实测后确定的参数

每天请求量/运行时长/下载量上限、内存和磁盘预留、来源冷却、自动重试次数、正常刷新周期以及历史保留窗口，需要结合代表教材运行数据确定。第一版采用保守默认和配置上限，不以复杂自学习调速作为前置条件。
