# 简化版题库数据库与教案抽题设计方案

> 适用范围：当前 7 个 Word 数学题库，以及后续用户上传的新教材、新章节、新知识点、新题目。
>
> 当前系统定位：**不生成新题、不生成答案、不生成解析，只把题库结构化，并按可配置规则抽题、组题、生成教案。**

---

# 1. 设计原则

当前六个有题章节的 Word，题目结构比较统一：

```text
题目ID / 页码
→ 来源信息
→ 题型
→ 难度
→ 标签
→ 题干 / 小问 / 图片 / 表格 / 公式
```

例如一道题通常可以解析出：

```text
ID：34928338
来源：25-26八年级下·陕西西安·期末
题型：解答题-应用题
难度：容易（0.85）
标签：根据概率公式计算概率、列表法或树状图法求概率、名校
题干：……
小问：(1)(2)
```

当前系统第一版不应做复杂平台化设计，而应坚持：

> **题库数据尽量结构化，抽题配置尽量简单。**

第一版只围绕当前题库真实已有字段和可确定性提取字段设计。

---

# 2. 第一版抽题规则

教师抽题时，建议采用以下流程：

```text
选择教材
↓
选择章节 / 小节 / 知识点
↓
设置该知识点需要几组题
↓
每组配置：
    出几题
    什么题型
    什么难度
    最多允许附带几个其他知识点
    最多几个小问
    放在哪个教学环节
↓
整节课配置来源偏好：
    最近几年
    省 / 市
    考试类型
    真题优先
    名校优先
↓
模拟候选题数量
↓
抽题
```

# 3. 第一版不需要让教师理解“硬筛选 / 软评分”

系统直接规定即可。

## 3.1 硬筛选

必须满足：

```text
教材
知识点
题型要求
难度范围
最多附带知识点数量
最大小问数量
题目必须可正常显示
同一道题不能重复
```

## 3.2 排序偏好

只影响优先级，不直接排除题目：

```text
最近几年
省份
城市
考试类型
真题
名校
```

这样教师不需要理解复杂规则术语。

---

# 4. “一组规则出几题”的配置方式

推荐每个知识点下面允许添加多条抽题规则。

例如：

## 知识点：列表法或树状图法求概率

| 教学用途 | 数量 | 题型 | 易度系数 | 最多额外知识点 | 最大小问 |
|---|---:|---|---|---:|---:|
| 基础检测 | 1 | 单选 / 填空 | 0.80~0.95 | 0 | 1 |
| 核心训练 | 2 | 解答题-应用题 | 0.65~0.80 | 1 | 2 |
| 迁移训练 | 1 | 解答题 | 0.50~0.70 | 2 | 3 |

系统最终生成：

```text
槽位1：基础客观题 × 1
槽位2：标准应用题 × 2
槽位3：提高迁移题 × 1
```

这种方式直接对应教师的思维：

> 一种训练类型，需要出几道题。

---

# 5. 为什么保留“最多额外知识点数”

当前题库一题可以挂多个知识点。

例如目标知识点：

```text
列表法或树状图法求概率
```

## 题A

知识点：

```text
列表法或树状图法求概率
```

额外知识点数：

```text
0
```

## 题B

知识点：

```text
根据概率公式计算概率
列表法或树状图法求概率
```

额外知识点数：

```text
1
```

## 题C

知识点：

```text
条形统计图
扇形统计图
平均数
中位数
总体估计
列表法或树状图法求概率
```

额外知识点数：

```text
5
```

所以教师设置：

```text
最多额外知识点 = 1
```

即可自动排除大型综合题。

第一版没必要额外设计：

```text
纯题
轻度综合
重度综合
综合度分数
综合度算法版本
```

直接使用“额外知识点数量”更加简单、透明。

# 6. 数据库总体结构

第一版推荐只保留 10 张核心表。

```text
教材 textbook
│
├── 上传文件 import_file
├── 知识树 knowledge_node
└── 题目 question
      ├── 题目知识点 question_knowledge_point
      └── 题目素材 question_asset

教案方案 lesson_scheme
│
└── 抽题规则 lesson_pick_rule

生成记录 lesson_generation
│
└── 生成题目 lesson_generation_item
```

```text
第六章 概率的进一步认识
└── 用树状图或表格求概率
```

对应：


# 12. 为什么年份、地区、考试类型直接存在 `question`

例如原始来源：

```text
25-26八年级下·陕西西安·期末
```

解析后直接保存：

```json
{
  "year_start": 2025,
  "year_end": 2026,
  "source_grade": "八年级",
  "source_term": "下",
  "province": "陕西",
  "city": "西安",
  "exam_type": "期末"
}
```

同时保留：

```text
source_raw
```

来源信息不完整时允许字段为空。

不能因为某道题没有年份、地区就不导入。

# 16. “额外知识点数量”如何计算

不需要额外建“综合度”字段。

抽题时直接计算：

```text
当前题目知识点总数 - 1
```

例如：

```text
目标知识点：列表法或树状图法求概率
```

题目只有这一点：

```text
额外知识点 = 0
```

题目同时有概率公式：

```text
额外知识点 = 1
```

如果还带统计图、平均数、中位数等：

```text
额外知识点 = 多个
```

教师配置：

```text
max_extra_knowledge_points = 1
```

即可排除大型综合题。

# 23. 第一版抽题查询逻辑

例如规则：

```text
知识点 = 列表法或树状图法求概率
题型 = 解答题-应用题
易度 = 0.65~0.80
最多附带1个知识点
最多2问
```

基础 SQL 思路：

```sql
SELECT q.*
FROM question q
JOIN question_knowledge_point qkp
  ON qkp.question_id = q.id
WHERE q.textbook_id = :textbook_id
  AND qkp.knowledge_point_id = :knowledge_point_id
  AND q.question_type = '解答题'
  AND q.question_subtype = '应用题'
  AND q.ease_coefficient BETWEEN 0.65 AND 0.80
  AND q.subquestion_count <= 2
  AND q.status = 'ready';
```

再计算：

```text
该题知识点总数 <= 2
```

因为：

```text
目标知识点1个 + 最多额外知识点1个
```

# 24. 来源偏好评分

第一版评分也不要太复杂。

建议只做四项：

| 项目 | 权重 |
|---|---:|
| 年份新旧 | 30 |
| 地区 | 30 |
| 考试类型 | 20 |
| 真题 / 名校 | 20 |

例如目标：

```text
最近5年
陕西西安
期末 / 中考优先
真题优先
```

题A：

```text
2026 西安 期末 名校
```

得分较高。

题B：

```text
2022 四川 模拟预测
```

得分较低。

两题都可以使用，只是 A 优先。

# 25. 候选不足时的简单放宽

第一版不要做十级自动放宽。

建议只做三级。

## 第一级：原规则

按配置正常抽题。

## 第二级：难度放宽

```text
ease_min - 0.05
ease_max + 0.05
```

## 第三级：题型和综合程度放宽

例如：

```text
解答题-应用题
→ 任意解答题
```

以及：

```text
max_extra_knowledge_points + 1
```

如果仍不足：

```text
直接提示教师：当前规则只能找到X题，计划需要Y题。
```

不要继续无限放宽。

# 26. 表9：生成记录 `lesson_generation`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 主键 |
| `scheme_id` | bigint | 使用的方案 |
| `seed` | bigint | 随机种子 |
| `status` | varchar | success / failed |
| `rule_snapshot` | json | 当时完整规则快照 |
| `file_url` | varchar nullable | 生成的 Word |
| `created_at` | datetime | 创建时间 |

保存 `rule_snapshot` 的目的是以后可以知道：

```text
这份教案当时到底用了什么抽题条件
```

不需要复杂模板版本体系。

# 27. 表10：生成题目 `lesson_generation_item`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 主键 |
| `generation_id` | bigint | 哪次生成 |
| `pick_rule_id` | bigint | 来自哪条规则 |
| `question_id` | bigint | 抽到哪道题 |
| `order_no` | int | 教案中的顺序 |
| `score` | decimal | 来源偏好评分 |
| `relax_level` | int | 放宽等级 |
| `created_at` | datetime | 时间 |

必须保证：

```text
同一个 generation_id 下 question_id 唯一
```

这样同一道题不会在同一份教案中重复出现。

# 32. 最终推荐

第一版系统最重要的原则是：

> **题目数据本身尽量结构化，但教案抽题规则保持非常简单。**

题库数据重点结构化：

```text
教材
章节 / 小节 / 知识点
题型
难度
年份
地区
考试类型
真题 / 名校
题干
小问
图片 / 表格 / 公式
```

教师抽题重点配置：

```text
知识点
出几题
什么题型
什么难度
最多附带几个其他知识点
最多几个小问
教学环节
```

来源只做优先排序：

```text
最近几年
本省 / 本市
考试类型
真题
名校
```

这样既能够完整承接当前 7 个 Word，又不会因为未来新增教材、知识点或题目而重新设计数据库。
