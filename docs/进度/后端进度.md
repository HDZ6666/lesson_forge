## 3. 必须保留的契约

- 新建/重试产生新业务任务；手动续采保持任务身份，建立新 Collector run 并继承已保存结果。
- 服务端重新校验教材属于选定正式版本，不能相信前端传来的来源范围。
- 对比使用稳定来源身份和任务绑定快照，不读取“最新一次采集”替代历史任务。
- CollectorClient 分页读取快照，验证运行、教材、计数、游标推进、响应大小；素材按 SHA-256 校验后保存到 BANK_ASSET_ROOT。
- snapshotComplete=false 时禁止完整应用，即使 status=completed、scanComplete=true 或进度=100。
- apply 接口更新正式表；候选 review 只保存审核决定；Publisher 是另一条离线发布路径，三者不可混称。
- 多教材应用使用按教材的状态 token；失败要回滚数据库事务，不能覆盖其他来源/教材。
- 已执行迁移保持原内容；历史 004/005 曾因格式化发生 checksum 漂移，不能再次批量格式化迁移解决新需求。

## 4. 当前待核实的问题

1. blocked/interrupted/failed 等终态是否都持久保存最新 run、计数和原始错误；历史任务 12 曾仍指向旧 run 19。
2. CLI 尾部帮助提示不能覆盖业务错误；应采用结构化错误码、错误层级、可恢复信息。
3. “扫描完成但有问题”的任务需要独立补采入口，不能只允许 blocked/interrupted 续采。
4. 新列表 API → 快照 → 正式字段映射与字典：题型、难度系数、来源分类、引用试卷、标签及素材类型需逐项验收；不要把 raw_data_json 留存等同于可筛选字段已映射。
5. qdid/qyid 是来源代码，不是系统 dict_code/dict_sort。正式难度使用现有字典值，完整题型保留原文；考法缺项的后续补齐结果待核实。
6. 最新 011 迁移在各部署环境是否实际应用；不能仅凭源码版本判断。
7. 生产 Compose 未展示独立 Publisher 消费进程；外部 Cron/systemd 是否运行需核实。
8. MySQL 连接源码已明确 utf8mb4；生产历史乱码修复记录不能替代未来部署的连接检查。

## 5. 无人值守恢复计划（待实现）

建议由 Service 统一持有业务任务的调度权，Collector 负责一次采集执行和页级数据。

- 持久字段：nextRetryAt、retryCount、retryPolicy、blockedReason、resumeRunId、leaseUntil；通过新迁移引入，不改历史迁移。
- 到期扫描并原子领取任务，避免多 worker、手动按钮、定时触发重复执行。
- 自动/手动恢复调用同一服务；遵守来源冷却时间，限制尝试次数和最长等待周期。
- Collector 离线时不重复创建 job；先核实远端是否已接受前一次请求。
- 重启后找回待执行计划；过期租约要先核对远端运行状态。
- 用户主动取消后关闭后续自动执行。
- 后端恢复轮询和采集重执行必须分别记录，保留每次运行及错误历史。
