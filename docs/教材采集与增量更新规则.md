# 教材采集与增量更新规则

更新日期：2026-10-13。

本文统一记录本次会话确认的采集范围、增量更新、断点续采、全量重跑及异常处理规则。与此前方案冲突时，以本文为准。此前关于追求来源全量覆盖、拆分筛选以突破分页上限、专项检查旧题变化的建议，不再作为本次需求。

## 1. 目标与范围

- 每个教材由独立教材任务处理，教材内逐个处理现有目录。
- 每个目录只采来源当前可访问的前 1000 页；不足 1000 页则到实际末尾。本文示例按每页 10 道题计算。
- 来源显示 4 万题、10 万题，不意味着必须采齐这些题目。
- 已保存题目持续保留，不因它们移出前 1000 页或本次未出现而删除。
- 日常增量运行只补头部新增和仍在当前窗口内的中断缺口，尽量跳过已保存范围。
- 用户可定期重新全量运行学科计划，重新扫描每个目录当前的前 1000 页。
- 不专门追查个别题目的删除、修改、重新归类或中间插入；采集时遇到变化可沿用更新规则处理，否则交给后续全量扫描。
- 不为取得窗口外历史自动拆目录、增加题型/年份筛选或改成倒序采集。沿用现有目录查询和固定排序。

“前 1000 页”是本次约定的访问窗口，不是每本教材合计 1000 页，也不是学科合计 1000 页。不能通过把配置改为 1500 就假定来源会开放更多内容。

## 2. 三种操作的区别

| 操作 | 行为 |
|---|---|
| 暂停后继续 | 保留当前执行方式及进度，处理待提交成果，从可靠断点附近继续，不因为恢复计划就全量重扫。 |
| 增量运行一轮 | 每个目录检查头部新增；接上已保存区域后，跳过已有范围，补仍在窗口内的未采部分和缺口。 |
| 重新全量运行一轮 | 每个目录从第一页重新扫描，最多到 1000 页。已有题仍需经过列表扫描，不能因接上旧题就提前结束。 |

全量运行仍然去重，不清空正式题库，不删除本次没有出现的旧题。全量运行中途暂停后继续，也应续接这次全量执行的进度，而不是再次从第一页开始。

“定期全量”的具体周期本次没有另行确认，本文不新增调度周期或自动切换规则。

## 3. 需要记录的进度

进度按当前教材、目录及固定查询范围分别保存，不能仅根据全局题库是否已有某道题判断目录是否处理过。

| 记录 | 用途 |
|---|---|
| 头部题号组 | 识别上一次保存过的头部区域，判断新增扫描是否已经接上历史。保留多道题，不只认最后一道。 |
| 连续可靠保存的范围及边界题号组 | 识别历史续采位置；页码作为位置提示，不能直接视为稳定游标。 |
| 已知失败缺口 | 记录并发或普通请求失败留下的未保存部分，不能被后面成功的页面掩盖。 |
| 当前执行方式与阶段 | 区分全量、增量，以及头部更新、断点续采、入库等阶段。 |
| 已抓取暂存与正式入库进度 | 已可靠暂存的成果继续提交，不重复抓取；未确认入库的数据不能删除。 |

不维护“这个目录永久采集完成”的业务结论，但必须保留本次执行进度和停止原因。

头部增量扫描中途失败时，要保留尚未接上旧范围的进度，不能仅因新第一页已经保存，就把整个头部更新标记为结束。

## 4. 增量运行流程

1. 处理已有、尚未确认入库的成果，保留其提交进度。
2. 没有历史记录的目录，从第一页开始，最多扫描前 1000 页。
3. 有历史记录的目录，从第一页保存新增内容。
4. 利用上次头部的多道题号及少量连续重叠页，确认是否接上本目录已保存区域。
5. 接上后，不再逐页重抓中间已保存的范围：
   - 以前已经保存了当前窗口内对应的旧范围：结束本次新增扫描。
   - 以前中断，未采部分仍在窗口内：定位旧边界，回退少量页面后继续补采。
   - 存在已知且仍在窗口内的失败缺口：单独补缺口。
   - 旧断点已经移出前 1000 页：不再追窗口外的未采历史，不新增人工处理问题。
6. 始终没有接上历史区域，则继续扫描，最多到第 1000 页。
7. 记录实际新增、关联、保存结果和本次停止原因，交由教材任务流程继续处理后续目录。

连续核对 2～3 页、断点回退约 5 页是本次讨论的示例值，不是已经验证的固定参数。业务要求是允许少量重复来确认位置，不依赖单题号，不因一次匹配失败就无条件整本重跑。

头部重叠停止是一种针对“新增主要在前面”的增量策略，不承诺发现所有中间插入和旧题修改。用户已接受由定期全量扫描处理当时窗口内的这些变化。

### 4.1 不得误用的停止条件

- 不能遇到一个已知题号就停：它可能来自其他教材或目录。
- 不能因为某页所有题全局都已存在就停：当前目录关联仍可能没有保存。
- 不能仅凭总题数差计算并信任续采位置：新增和删除可能同时发生。
- 不能把不同页码反复返回同一页面视为有效推进。
- 全量运行不使用“接上历史区域就结束”的增量早停规则。

## 5. 三个常见示例

### 5.1 上次保存 1000 页，本次新增 200 页

| 当前位置 | 内容 |
|---|---|
| 第 1～200 页 | 新增内容，需要保存。 |
| 第 201～1000 页 | 原第 1～800 页，已经保存。 |
| 第 1001～1200 页 | 原第 801～1000 页，已经保存，但现在访问不到。 |

本次抓取新增的约 200 页，在第 201 页附近接上旧头部，再核对少量重叠页后结束。通常约请求 200 页加少量核对页，不重新请求全部 1000 页。

### 5.2 上次保存到 300 页，本次新增 200 页

前提：原第 1～300 页连续可靠保存，第 301 页尚未成功；新增全部位于头部，旧题顺序基本稳定。

- 当前第 1～200 页：抓取新增。
- 当前第 201～500 页：对应原第 1～300 页，可以跳过已经确认保存的范围。
- 当前第 501 页以后：原来尚未采到，定位边界后从第 500 页附近回退少量页继续，最多到 1000 页。

不是从第一页连续重抓到 1000 页，而是“头部新增”和“窗口内未采部分”分段处理。

### 5.3 没有明显新增，旧边界仍在 300 页附近

核对少量头部页面后，定位原第 300 页附近的边界，回退几页继续未采部分。重复题目去重，避免重抓前面几百页。

## 6. 旧断点移出前 1000 页的处理

### 6.1 已保存 990 页，新增 200 道题（20 页）

前提：原第 1～990 页连续可靠保存，第 991 页遇到防护；新增在头部，旧题顺序基本稳定。

| 现在的位置 | 对应内容 | 保存情况 |
|---|---|---|
| 第 1～20 页 | 新增的 200 道题 | 尚未保存，需要抓取。 |
| 第 21～1000 页 | 原第 1～980 页 | 已保存。 |
| 第 1001～1010 页 | 原第 981～990 页 | 已保存，保留正式库数据。 |
| 第 1011 页之后 | 原第 991 页之后 | 尚未保存，已在当前访问窗口外，不再追。 |

本次流程：

1. 保存当前第 1～20 页的新增题目。
2. 在第 21 页附近，通过题号组确认接上本目录原来的头部。
3. 再核对第 22、23 页等少量重叠页面。
4. 结束本次增量更新，不请求第 1010 页，不重抓第 24～1000 页，不拆分查询。

示例中约请求 23 页。可以停止的原因是：当前前 1000 页由“新保存的 20 页”和“此前保存的 980 页”组成。

建议展示：

> 本次新增 200 道题，已接上历史保存范围，增量更新结束。旧断点已移出前 1000 页，本次不再续采该位置。

上述判断不能掩盖已知失败缺口。若旧范围中有缺口，仍在当前窗口内的部分需要单独处理。

### 6.2 新增超过 1000 页，旧头部也访问不到

假设两次运行之间新增了 1200 页，原来的第一页移到当前第 1201 页：

1. 从当前第一页开始抓取。
2. 始终没有找到上次头部题号，继续扫描。
3. 到第 1000 页正常停止，只保留当前可访问的前 1000 页成果。
4. 不继续寻找第 1201 页，不追当前第 1001 页之后的数据。

因此，“断点移出窗口”不会产生特殊补救任务：能接上旧范围则提前停止，接不上则最多扫描到窗口上限。

## 7. 调整后的 14 类情况

| 编号 | 情况 | 处理规则 |
|---|---|---|
| 1 | 首次采集 | 从第一页开始，最多前 1000 页，不足则到实际末尾；仅记录本次执行结果。 |
| 2 | 中断后排列基本没变 | 从可靠断点附近回退少量页继续，重复去重，不重扫全部旧页。 |
| 3 | 头部新增、旧边界仍在窗口内 | 补新增，接上旧范围；再补仍在窗口内的未采部分及缺口。 |
| 4 | 旧断点移出 1000 页 | 保留旧题，只更新当前窗口；不拆目录、不加筛选、不追窗口外历史，不因此报故障。 |
| 5 | 来源总数超过窗口容量 | 到 1000 页正常结束，不因来源仍有更多题而标记待补齐或要求人工处理。 |
| 6 | 某个锚点题号消失 | 用多题号识别重叠；不能识别则继续扫描，最多到 1000 页，不专项追查单题。 |
| 7 | 总数变化与位置变化不一致 | 总数仅供展示或定位参考，以题号重叠确认保存范围。 |
| 8 | 排序或筛选变化 | 本次不新增此功能；沿用当前固定查询方式，不自动切换条件。 |
| 9 | 中间插入、旧题内容变化 | 不做专项历史复核；遇到则处理，否则由后续全量扫描处理当时窗口内的变化。 |
| 10 | 并发中间缺页 | 保存后面成功页，单独记录失败缺口；最大成功页码不能冒充连续完成进度。 |
| 11 | 普通超时、服务错误、解析失败 | 有限重试，仍失败则记录目录、页码和原因并保留成果，后续续采或全量重跑处理。 |
| 12 | 验证码、防护、来源限流 | 保留成果，暂停受影响来源；验证完成或限制解除后继续，不能将防护响应当空页。 |
| 13 | 多个页码重复返回同一页面 | 停止无效翻页，记录重复响应停止原因；不得把重复页计为有效新增。提前出现时不冒充已经扫描到 1000 页。 |
| 14 | 重复题目、已抓取未确认入库 | 正文去重并补目录关联；未确认入库成果保留，确认后清理临时数据；分别记录采集与入库进度。 |

这些情况可能同时发生。重复题目不等于重复页面，重复页面也不等于本目录没有新的关联需要保存。

## 8. 保存与入库

例如已经可靠暂存到第 300 页，但只正式入库到第 280 页：

- 第 281～300 页的现有成果继续提交，不因为入库滞后就全部重新抓取。
- 第 301 页以后按采集断点规则继续。
- 同一题在多个教材、目录、知识点出现时，复用题目正文并保存对应关系。
- 提交超时但结果不明确时，核对或幂等重试，不能直接删除临时成果。
- 临时成果只有在入库已确认且不再有其他依赖时才可回收；正式题目及其有效素材继续保留。

本文件规定业务语义，不将“保存规则已确认”表述为现有快照/入库协议已经改造完成。

## 9. 页面和结果口径

不展示目录永久“全部历史采集完成”的结论。保留以下信息：

- 当前教材、目录、页码以及全量/增量/续采阶段。
- 最近更新时间、本次新增题目和新增关联数量。
- 已可靠保存、已正式入库、尚待提交的成果。
- 本次停止原因和仍在窗口内的真实失败缺口。

正常停止原因包括：增量已接上保存范围、达到 1000 页上限、到达来源实际末尾。人工暂停与异常中断分别展示。

旧断点超出窗口、来源题目总数大于窗口容量，不单独产生人工处理问题。超时、防护、解析失败、入库失败等真实故障仍保留定位信息和执行历史。

## 10. 后续实现的核对示例

- 已保存 1000 页、新增 200 页：增量模式只处理新增及少量重叠页；全量模式仍扫描到本次窗口末尾。
- 已保存 300 页、新增 200 页：跳过确认已保存的中段，继续补当前第 500 页附近之后的未采部分。
- 已保存 990 页、新增 20 页：补新增并确认重叠后结束，不请求窗口外旧断点，不新增补救任务。
- 新增超过 1000 页：到第 1000 页正常结束，不因为找不到旧锚点而无限寻找。
- 第 301 页失败、302～308 页成功：保留 301 页缺口，不能写成连续完成至 308 页。
- 头部增量中断：保留剩余新增扫描进度，不能提前替换基线而漏掉尚未扫描的新增区间。
- 全局已有某题但当前目录关系不存在：补关系，不能因题号存在而跳过整个目录。
- 到第 1000 页是正常范围结束；返回验证码、提前重复响应或入库失败必须保留各自真实原因。
