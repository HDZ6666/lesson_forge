# 数学教材增量采集、顺序调度与存储回收方案

> 后续需求已收敛：采集范围、增量续采、全量重跑和异常处理以 [教材采集与增量更新规则](../教材采集与增量更新规则.md) 为准。本文保留为早期方案；其中追求窗口外历史覆盖、自动拆分筛选、专项复核旧题变化等建议已被新规则替代，其他架构建议也不能直接视为已确认实施范围。

状态：设计建议，尚未实施。本方案对应用户提出的“新增在前、续接旧进度、每本结束保留已采题目、失败后继续下一本、置顶下次执行、清理中间数据”。基于线上 2c485f8 和现有源码核查。

## 1. 推荐的目标行为

155 本教材作为持久化任务清单，每轮给每本一次有界执行机会。每本先补新增，再补历史缺口，按小批次核验入库；当前教材收尾后执行下一个符合条件的任务。失败教材默认进入后续轮次的补采清单，人工可“设为下一个执行”，不打断当前采集。

本轮处理结束、按配置上限完成、来源范围完整覆盖是三个概念，界面分别显示。达到 1000 页不等于来源全量完整。

取消每次运行的全量正文快照复制，保留轻量运行摘要、目录覆盖信息、幂等批次收据，以及有上限的未提交临时批次。正式题库成为已确认题目内容的主要存储；人工内容、其他来源内容和已保存的可靠答案仍受现有合并规则保护。

## 2. 按目录维护两个进度，而不是只记页码

目录身份至少包含来源、学科、教材、章节/知识点、筛选条件与排序。不能只按全局题号判断一个目录是否采过。同一题在另一本教材或另一知识点出现，可能只需增加关系，但该关系不能省略。

每个目录保留：

- 最新增量边界：最近一次确认入库的头部题号组及必要内容版本摘要。
- 历史连续覆盖边界：上次连续处理到的题号组、当时页码提示、观察时间。
- 未处理缺口：失败页或题目 ID、失败类型、重试时刻，以及已取得但未提交的批次。
- 覆盖状态：未开始、增量已追到旧边界、历史待补、受页上限限制、待人工处理、已验证覆盖。
- 配置版本：排序/筛选变化需要新的覆盖身份，不能复用不兼容断点。

题号是定位依据，页码仅是提示，来源总题数也不能充当稳定游标。来源若有经过验证的稳定 cursor 或更新标识，优先使用；目前系统使用“最新”排序和页码，没有已经验证的稳定增量 cursor。

## 3. 新增在前时怎样少抓

每次访问目录先从第 1 页向后抓新增，直到看到此前确认的重叠区域。每页先做身份、结构与内容检查，新题或变化题入库，已存在内容复用，但补齐本目录的新关系和必要素材引用。

不能遇到第一个已知题号就停：该题可能来自另一本教材，可能是置顶/重排，也可能页面其他题仍未见过。可采用多题锚点、连续多页重叠与局部一致性检查作为低成本停止条件；连续页数例如 3 页只是待验证参数，不是来源站点承诺。

即使连续页重叠，在来源可能任意重排、删除、补插或回填旧题时也无法从有限请求证明后方绝无新题。界面应表述“新增扫描已追到已知边界”；通过低频抽查或分段复核处理旧内容变化与潜在漏项，不能声称永久绝不漏题。

只有上次历史范围完整处理过，头部重叠才能作为这次增量扫描结束的依据。如果历史仍有未采目录/页面，结束头部扫描后必须转入历史补采。

## 4. 历史如何继续

例：上次连续采到第 200 页，本次新增 120 道，若稳定每页 10 道，旧边界可能移到约第 212 页。程序可以用这个数作搜索提示，但必须在当前响应中找到旧题号组，才能从重叠区继续。

步骤：

1. 先完成一次有预算的头部增量扫描。
2. 依据旧页码、已观察新增量寻找历史边界，在小窗口内校验多个题号及相对顺序。
3. 锚点确认后带一定重叠向后补采；批次幂等合并消除重复写入。
4. 找不到锚点时扩大有界搜索，或重新扫描对应目录片段并标记需要重建覆盖；不凭估算跳过未知区域。
5. 中间失败页独立进入缺口队列。即使第 200 页成功，第 198 页失败，也不能把 1–200 页标为连续完整。

头部新增与历史补采应分别有预算，防止热门目录持续新增、历史永远轮不到。教材内部也需轮转未完成目录，避免每轮都从同一个大章开始耗尽预算。

## 5. 1000 页上限的含义

现有配置是目录最大页码。若旧边界已在 1000 页，新增使它移动到 1012 页，则硬上限 1000 阻止继续历史补采；这是明确的覆盖限制，不是续采算法可以凭空解决的。

建议保留“每目录最大页码”作为来源访问范围限制，再单独引入每次访问的工作预算（时间/请求数），两者不能混为同一个 maxPages。来源只返回前 1000 页时，改为 1500 也不保证能拿到新内容，仍需重复页早停、允许的更细目录/筛选、或明确显示不可覆盖范围。

## 6. 小批次提交，取消整本快照复制

建议流程：采集页 → 持久化小批次待提交数据 → 题干/素材/关系核验 → Service 幂等合并 → MySQL 同事务提交数据、收据和断点 → Collector 收到确认 → 释放该批中间正文。

Collector 不持有 MySQL 写权限；沿用 Service 作为正式库写入方。初期建议采集/入库串行或小窗口流水线，避免当前 3.6 GiB 主机被全学科多浏览器并行压垮。

“不做快照”应落实为不复制整本教材的全量运行快照，而不是取消所有持久化待提交记录。仍需：

- 幂等批次标识（运行、目录、批次或内容摘要）与提交收据；同一批重放不重复计数、不重复创建题目。
- 正式数据与成功断点同事务推进。收到网络超时可重试；未确认成功不得删除临时文件。
- 页已抓到、已验证、已正式提交是三个不同计数；“已采”不可冒充“已入库”。
- 无效题、缺图题和待修复关系保留最小必要内容与问题摘要，不无限保存全部成功页；它们不得被标为完整覆盖。
- 中断时，已提交数据立即可用；已抓但未提交的批次后续先补入库，不重新抓整本。

当前代码要求任务终态且快照封存后才能进入增量入库，不能简单删掉封存步骤就边采边写。需要改变绑定/批次协议，并保留现有题干、素材检查、人工数据保护、去重和不删除未观测题目的合并语义。

## 7. 哪些故障继续下一本，哪些暂停全局

| 情况 | 处理 |
|---|---|
| 单页网络错误、解析异常、单题素材失败 | 有限重试；记录缺口，保存其他成功批次；必要时结束当前教材并进入下一本 |
| 当前教材长期无新增、达到预算或页上限 | 收尾，明确部分完成/受限，交给下一本；保留该教材续采进度 |
| 普通单教材失败 | 后续轮次再补；可由用户设为下一个执行，不自动无限抢占队首 |
| 来源验证码、站点公共冷却/限流 | 保存已取得成果，暂停受影响来源队列，等待规定冷却或人工处理；换教材不能绕过公共暂停 |
| 磁盘不足、数据库不可用、共享写入通道阻塞 | 暂停新采集并做背压；保留未提交批次；无法写正式库时不承诺全部已正式保存 |
| 人工暂停/取消当前采集 | 停止发新请求，安全落下已取得批次；界面显示尚待提交部分；不擅自恢复全计划 |

未提交队列需要总字节数、年龄及批次数限制。存在少量可隔离的坏题不阻塞全学科；公共入库失败时不能继续把 155 本全部抓进临时盘。

## 8. 155 本任务轮转与“设为下一个”

- 同一教材最多一个当前执行/待执行项，重复点击不创建多份相同任务。
- 每轮给各教材一次可配置预算的执行机会，结束即释放采集槽；成功成果与缺口均记录。
- 没完成的教材保留 needsRefill，不把“尝试过”写成“完整完成”；下一轮从持久化进度继续。
- “设为下一个执行”：一次性提到待执行队首，当前任务不被抢占；当前任务收尾后自动执行它，然后回到正常顺序。
- “调整教材顺序”：修改长期轮转顺序；与一次性优先执行是不同按钮。
- 多个优先项按清晰可见顺序执行，可取消优先；失败退避必须保留，公共故障未解除不能强制启动。
- 当前任务收尾包括确认已取得有效批次的提交结果，或把未提交部分持久化成待处理项；全局入库阻塞时不启动下一采集。
- 页面上的“下一个”由后端实际调度器返回，包含人工优先、冷却、暂停与依赖判断，不由前端把表格第二行当作队首。

已有代码可复用任务队列、执行历史、dispatch_priority、单本提前执行、顺序调整、批次幂等与增量合并；需要重做进度继承、执行级入库绑定与回收，不是全部推倒。

## 9. 页面建议

顶部固定显示：

- 计划状态：执行中/暂停/资源等待，当前轮次，已尝试教材数和完整覆盖教材数分别计数。
- 当前采集：版本+教材+章节/知识点、页码、头部增量/历史补采、开始时间、最近有进展时间。
- 数据落地：新增题、更新题、新增关系、已正式入库、待提交、待修复。
- 正在收尾/入库的教材及积压字节；如与当前采集不同，分开显示。
- 下一个执行的教材、原因（正常顺序/人工优先/重试），若不能开始则给出阻塞原因。
- 待执行队列、失败和待补列表：设为下一个、取消优先、查看日志、暂停当前、暂停计划。

每本教材区分“本次执行结果”和“累计覆盖”。历史失败只是一次执行记录，不代表所有已保存题目无效；本次正常结束也不一定代表来源全量齐备。

## 10. 可以删除与必须保留

| 数据 | 生命周期建议 |
|---|---|
| 已确认入库的批次正文、重复原始响应 | 释放；不等全学科结束 |
| 全量按 run 克隆的正文 | 新流程取消；旧成果逐个对账迁移后回收 |
| 未确认入库批次 | 持久化且限额，直到重放成功/明确处置 |
| 失败/缺图题 | 最小隔离数据和问题证据，受保留预算管理 |
| 正式题目及其有效素材、关联 | 持续保存，遵守人工内容保护 |
| 头部锚点、历史边界、缺口和覆盖摘要 | 长期保存；通常远小于全量正文 |
| 执行摘要、批次收据和必要日志 | 按审计与幂等重试窗口保留 |
| 原始成功日志/页面 | 抽样、限额和期限归档，避免无限增长 |
| MySQL binlog | 由数据库复制/恢复策略单独管理，不能按教材结束直接删除 |

素材要确认正式存储可用且无其他待提交引用后，才能清理采集缓存。可评估共用内容寻址存储，但需要引用和权限设计，不能仅因为正式表有路径就删除实际文件。

## 11. 建议实施顺序

1. 先修任务显示和“设为下一个执行”，明确当前采集/入库/实际队首与错误原因；现有排序能力复用。
2. 建立目录级头部锚点、历史连续边界与缺口，替代复制旧快照来继承进度。离线模拟新增、重排、删题、跨教材相同题和空页。
3. 引入有限待提交队列与批次幂等提交，复用正式库合并和质量核验。资源背压前置。
4. 在一本小教材上同时核对新旧结果；再用大目录验证上限和重叠，模拟断网、进程被杀、提交成功但响应丢失、磁盘水位。
5. 对已有旧快照确认“已入库/仍需修复/含唯一数据”后迁移和回收，再扩大到 155 本；不直接丢弃旧库。

验收重点：重跑无新增时不重复写正文；已确认题目中断后仍可用；重放不重复计数；失败页不被最高页码掩盖；未提交内容不会被清理；置顶在当前任务之后执行且不复制任务；数据受限不伪装全量完成；连续多轮临时占用有上界。
