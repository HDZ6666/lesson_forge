### 2.2 不能沿用的旧实现假设

1. **单活动任务不等于自动排队**：Service 与 Collector 创建 queued 任务时都占执行槽；新计划需要将持久待办和实际派发分开，并复用已有所有者保护。
2. **封存不等于可直接入库**：Collector 已能保存不可变的不完整终态，常规 apply 仍要求成功、完整、零错误，且一次事务提交；新部分成果协议和逐条质量隔离尚未实现。
3. **现有 apply 不等于无损增量**：会整理受管理目录关系，并根据当前范围重新启用/禁用题目。新流程不能把来源题目再次出现当作撤销老师禁用的理由，跨教材关系也需明确保护。
4. **旧教案不等于新编辑器**：当前 DAO 一次加载目录候选到内存，pick_engine 使用 0～3 级自动放宽；Word 仍含教学目标、过程、板书等。新规格要求严格条件、分页选题、保留已选、局部补齐、自由分组和仅题目导出。

### 2.3 仅作为历史查证的记录

2026-09-30 的任务 18 入库 49,865 题、旧生产部署和 MySQL 恢复记录，保留在[旧巡检](archive/项目巡检与优化清单-2026-09-27.md#10-是否全部完成重新核验2026-09-30)。本轮没有重查服务器，不能据此认定全部教材覆盖或整套恢复完成。源码中仍缺的性能、权限边界、资源预算及恢复验证继续归属 C14、L04、L07～L08，不因归档丢掉。
