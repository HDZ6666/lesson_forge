## 1 已确认的需求

2026-10-09 用户明确调整交付范围：本轮先完成本文要求的代码重构；不以当前题量、真实采集速度或全教材覆盖作为代码完成的前置条件。源码使用隔离 worktree，实际教材采集情况由用户部署后验证。资源预算与来源暂停能力保留为配置和运行行为，不再通过采集吞吐评估延长本轮开发。

| --- | --- | --- |

| R13 | 保持当前项目结构，隔离重构 | 保留 `pc / service / collector` 三端；后续在独立 worktree 和测试环境实施 |

| R16 | 网页编辑后保存和导出 Word | 补齐、换题与调整条件保留已有人工结果；严格筛选不自动放宽；导出使用同一保存版本和题目顺序 |

## 2 最终功能结构

```text
题库管理
├─ 学科管理
├─ 版本管理
├─ 教材管理
├─ 目录管理
├─ 题目管理
└─ 教材浏览

同步中心
├─ 同步总览
├─ 教材发现
├─ 自动同步计划
└─ 同步任务
   ├─ 全部任务
   └─ 待处理问题

教案生成
└─ 一个主页面，包含筛选组题、内容编辑、预览换题、草稿历史和 Word 导出
```

“全部任务”和“待处理问题”是同步任务页面内部的标签，不新增侧边菜单。账号、权限等通用系统功能继续沿用现有底座，本次只调整业务模块。

### 2.1 题库管理

| 页面 | 处理方式 | 功能与调整 |
| --- | --- | --- |
| 学科管理 | 新增 | 维护学科及适用学段、启用状态、来源映射；第一阶段接入数学，其他学科逐个验证解析能力 |
| 版本管理 | 保留并扩展 | 保留来源与人工版本、新旧版标识；增加学段/学科筛选，避免不同学科同名版本混淆 |
| 教材管理 | 保留并扩展 | 维护唯一教材资料；展示累计可用题量、目录覆盖、最近同步、未解决问题及下次安排；“立即同步”进入统一队列 |
| 目录管理 | 保留并适配 | 维护章、节、知识点及层级；保留稳定 ID，明确来源与人工维护边界 |
| 题目管理 | 保留并完善 | 查询内容与素材、维护人工题目、启停来源题目；同步不得撤销人工禁用；图片区分加载中、可用、下载缺失与请求失败，并支持重试 |
| 教材浏览 | 保留并完善 | 通过学段、学科、版本、教材和目录浏览正式可用题目；用于检查采集效果和日常查题 |

业务启停与自动同步启停分开：暂停采集不删除或隐藏已有题目；人工禁用题目影响抽题资格，下一轮同步不能自动重新启用。具体展示沿用现有权限边界。

### 2.2 同步中心

| 子模块 | 主要职责 | 不承担的职责 |
| --- | --- | --- |
| 同步总览 | 学科教材数、本轮目标、有题/待补齐/待处理情况、当前任务、下一本、公共暂停原因、资源和存储摘要 | 不维护另一份教材资料，不重复提供一套执行器 |
| 教材发现 | 刷新来源的版本/教材清单，展示新增、改名、本次未发现和发现历史 | 不要求正常新增项逐个审批，不直接采集全部题目 |
| 自动同步计划 | 学科范围、循环策略、新版优先、运行预算、启停和单本调度覆盖项 | 不将全部教材塞入一个内容任务，不绕过来源冷却 |
| 同步任务 | 一本教材一次运行的进度、结果、日志、补采和重跑；集中查看待处理问题 | 不再拆出独立入库中心、日志中心或强制审核中心 |

教材发现与教材管理使用同一教材身份。发现过程记录来源观察结果；通过身份校验的正常新增项自动登记。归属冲突或疑似错误单独处理。一次教材发现可以覆盖一个学科，属于元数据操作；“一本教材”约束针对内容同步任务。

自动计划覆盖整个学科，单本手动操作只是同一计划/队列体系中的一次请求。调度列表、教材页的同步信息和总览从相同状态读取，避免三处维护不同事实。

### 2.3 教案生成

老师自行确定教学内容，按条件筛选与组织题目，网页编辑后导出 Word。先列内容配题和直接从题库选题共用草稿，同一内容支持多组题型、难度和数量条件。教案端只展示题干及必要素材。

沿用现有 lesson 插件、历史与快照能力，改为自由内容分组、严格筛选、手动选题、局部补齐、换题及排序。详细交互、数据模型和接口统一见第 8 节，实施状态只见[实施任务清单](实施任务清单.md)。

## 3 业务流程与单本任务

2026-10-10 确认：用户创建一个学科同步计划，系统负责串联教材发现、逐本采集和自动入库。参考主分支已有采集能力，不整体回退或覆盖 Collector。

```text
创建并命名学科同步计划
    ↓
教材发现任务进入统一队列
    ↓
发现成功，版本和教材自动登记成功
    ↓
确定本轮教材范围，生成全部单本教材待办
    ↓
逐条排队执行：采集 → 封存 → 核验 → 合格题目分批入库
    ↓
汇总完整、部分完成和异常；到期开始下一轮
```

一个学科保留一个持续计划，每轮使用“计划名称 · YYYY-MM-DD HH:mm · 第 N 轮”区分（UTC+8）。后台身份使用计划 ID 与轮次，不能只按日期分组；同日多轮不会混淆。发现任务及本轮单本任务保存同一名称快照，计划改名不改写历史。任务列表可按批次名称/日期搜索，也可从计划详情精确进入本轮列表。

发现后根据已启用且未人工排除的正式教材一次生成本轮全部待办，不是执行完一本才创建下一条。已有同教材未结束任务时避免重复启动，待其结束后补建；已有可恢复入库成果优先处理入库。固定本轮目标，新发现教材在后续轮次纳入。新版优先，旧版保留。

2026-10-11 明确去重语义：题目以学科＋来源＋来源题号去重，多小题保留整道大题及小题数量；相同题目可关联多个教材、目录及知识点，已存在且未变化的正文跳过重写但补齐新关联。目录身份以学科＋来源＋教材＋来源节点ID唯一，共享知识点出现在其他教材不构成归属冲突，不移动或覆盖原教材的目录。

每条教材任务包含采集、检查、入库阶段。采集失败但有合格封存成果，仍可部分入库；入库失败保留已提交批次。教材发现失败或登记未完成时，不创建依赖它的新一轮教材任务；可在计划中重试发现或登记。

新一轮周期更新重新扫描当前页面，按来源题目 ID 合并，不能把上一轮页码当成本轮完整覆盖证明。显式补采仍保留既有成果及受控断点恢复能力。正常题目不要求人工逐题审批，问题项单列。

教材发现与题目同步均通过持久队列派发。来源验证/限流、预算、资源或服务暂不可用时，未执行任务保持排队并展示原因；启动时 Collector 明确返回 423 也回到等待，不记为采集失败。真正的单本采集错误只影响该教材；来源验证仍需处理后恢复。服务自动运行总开关及实际部署参数保持显式配置，开启计划不绕过它们。

界面导航按“同步总览 → 学科计划 → 教材发现 → 教材任务”排序，与侧栏一致。总览说明自动流程，首次操作引导创建计划。已有计划优先展示批次名称、进度、队列和异常，名称/频率等设置收起；手动发现、单本采集作为辅助入口。核验和入库在各教材任务中展示，不再要求用户依次点击四个页面。

### 分页并发设置（2026-10-10）

学科计划提供1、2、4、8页并发选项，默认8页。优先级为单次任务自定义、学科计划、服务器默认；只影响同一本教材内部同时请求的列表页数，不改变每页题量、多教材排队、素材并发和请求间隔。

创建教材任务时保存实际并发、来源和继承值快照，计划修改不改动已有任务。手动任务默认继承同学科计划，没有计划则使用BANK_DEFAULT_LIST_CONCURRENCY（部署映射COLLECTOR_LIST_CONCURRENCY）。尚未派发的持久待办可单独修改或重新继承当前计划，提交时核对设置令牌并与派发共用行锁；已派发/运行中拒绝修改。暂停后继续时，新建关联补采任务重新继承当前计划；原任务明确自定义的并发保持自定义，历史记录不改写。终态任务可设置新并发后重跑，保留原记录。Collector保存每任务并发并纳入派发幂等身份，重放不能偷偷换参数。浏览器有头模式及来源公共控制仍由部署管理。

### 3.1 操作定义

| 操作 | 行为 |
| --- | --- |
| 立即同步 | 进入统一队列；若同教材已有任务，定位已有任务或调整优先级，不重复启动 |
| 暂停整个计划 | 停止该计划的发现、采集、核验、入库、重试及未来轮次；立即请求取消发现/采集，核验和入库在安全点暂停，当前数据库批次完成或回滚；成果和断点保留，收尾完成才显示“已暂停” |
| 继续计划 | 从暂停处继续；被停的发现重新执行，不登记半份清单；入库复用已提交游标；未采完教材创建关联补采任务并优先执行，然后恢复原队列 |
| 结束本轮 | 停止当前工作并取消未完成队列，保留成果；显式选择是否继续自动更新。结束后可以开始新一轮，不提供原轮“继续” |
| 关闭自动更新 | 当前轮继续执行，结束后不开始下一轮；与暂停整个计划分开 |
| 调整教材顺序 | 拖动、上移/下移、移到最前；保存学科计划顺序，影响本轮尚未派发任务及未来轮次，已执行/正在执行的任务不变；新发现教材追加到末尾 |
| 提前执行/再同步一次 | 已排队教材提高这一次优先级并允许覆盖并发；忙碌教材定位已有任务；没有未结束任务则新建单本任务。计划暂停时必须明确选择“仅执行这一次，不恢复整个计划”；不改整轮下次时间 |
| 暂停教材自动同步 | 停止该教材后续自动派发，保留题库；当前任务是否停止通过独立操作表达 |
| 停止当前任务 | 在安全边界停止后续工作，保留已采集及已提交结果；进行中的事务明确完成或回滚，不假装整轮撤销 |
| 补采 | 优先处理已知失败与未覆盖范围，核对断点有效性后执行 |
| 重新同步 | 重新扫描当前来源内容，按来源 ID 合并，不清空已有题目 |
| 重试入库 | 使用已保存且可验证的采集结果重试数据库处理 |
| 跳过本轮问题 | 记录原因与后续安排，不标记问题已解决，也不宣称整本完整 |

手动操作仍遵守资源与来源限制。公共紧急暂停与“暂停计划”分开：前者可要求当前相关任务在安全点停止。

### 3.2 状态与数量口径

必须分别保存和展示运行阶段、入库结果、覆盖情况。最终数据库枚举在实现时细化，不继续用一个 `completed` 同时表示采集结束、全部入库和来源全量覆盖。

示例显示：“本轮已结束；已入库 30,000 道；仍有未覆盖范围；已安排下次同步。”

任务详情展示来源标称数及观察时间、本次去重题数、本次合格数、新增/更新/不变数、入库失败数和已知缺口。教材页展示累计正式可用题数及目录分布，累计数与本次数不能混用。

用户示例中的第一轮 30,000/40,000、第二轮 39,000/41,000 都允许形成可用结果。累计按稳定来源 ID 合并，不能直接相加，也不能用第二轮数量覆盖累计数量。父子目录可包含同一道题；来源标称数口径或时间不同，不能仅凭差值断言具体漏了多少题。

## 4 自动运行与数据规则

### 4.1 动态教材清单与基础覆盖

定期按来源、学段和学科刷新清单。新增教材进入首次覆盖待办；改名不创建重复教材；只有完整清单刷新才能用于判断缺席，失败或截断的发现结果不能下线教材。单次未发现只记录观察，不删除旧题。教材被人工暂停或排除后，后续发现不能擅自恢复调度。

每轮保留目标清单与目标数，同时展示最新总数。新教材进入后续待办，不使本轮验收目标无解释地变化。第一阶段优先让所有纳入教材都有一批通过检查的可用题，再持续提高覆盖；不能只围着第一本反复补采。

“有可用题”“有较多目录覆盖”“完成范围扫描”是不同指标。来源无题或长期不可访问的教材人工确认后单列，不静默从分母剔除。是否达到进入教案阶段的条件依据教材台账验收，不强求任一轮抓到来源标称的全部题目。

### 4.2 调度与来源反馈

初期同一时间只采一本，采用固定规则及明确上限。首次顺序新版优先，之后按用户保存的教材顺序执行，动态新增教材追加；“提前执行”只改变一次优先级。每轮遍历全部参与的教材，重试有预算，避免坏任务无限占用。

每次派发检查：计划与任务允许执行、同教材无重复活动任务、来源无冷却、资源有余量、当日预算未耗尽、待入库积压可控。整轮开始后全部待办按顺序执行，不再按单本刷新日期派发；明确授权的单本同步可在计划暂停时仅执行一次。待办队列不占执行槽位，派发时再获取执行权。

记录请求量、延迟、429/验证事件、成功页和重试页、下载量、耗时、内存峰值及磁盘增长。运行异常降速或暂停，稳定后才在配置上限内恢复；不通过故意触发来源阻断来寻找速度极限。

教材发现同样遵守来源预算与冷却；429 返回的 Retry-After 纳入最早重试时间，不能另开来源会话绕过。每天最大启动本数可作为保护上限，但不是必须完成的产量。同一本可以跨天恢复。未来不同学科使用同一站点时，共享来源限制；不能通过换学科或换教材绕开冷却。

共享日预算使用明确的 UTC 日界，界面按本地时区显示恢复时间；重启、重跑和人工解除验证不能清零已用量。主动采集请求包含重试、探针和素材兜底；如实现只计程序显式请求，必须说明未计入的浏览器自动请求和重定向，不能当作所有网络流量的硬上限。每日请求数、教材题目采集启动次数、采集秒数、素材下载MB均在同步中心「每日额度设置」中配置，默认0表示不限，不再作为启用自动运行的前置条件。所有学科与手动任务共用，配置保存在Collector SQLite中，重启保留，后续请求读取最新值；修改额度不清空用量，不解除计划暂停或网站验证。主机资源水位与入库积压检查继续生效。

2026-10-11 调整：采集与核验/入库独立排队，一本采集、一个入库任务可重叠；同教材的入库/补采依赖只约束本教材，不阻塞整个学科计划。采集优先，入库在安全断点让出内存并自动恢复。生产默认采集启动需要1536 MiB可用内存、入库需要1024 MiB，运行中采集仍保留512 MiB水位；分页并发保留用户设置8。`BANK_SYNC_MAX_PENDING_IMPORTS=0`默认不按本数阻断采集，非零仍可选；磁盘低水位始终生效。总览分别展示正在采集及质量检查/入库，已过期的派发原因不当作当前原因展示。

成果自动回收：已处理全部题目且无暂缓题目的入库SQLite及WAL/SHM可自动删除，保留轻量锁文件和数据库入库记录。采集器旧快照需入库结束满`BANK_RESULT_RETENTION_HOURS`（生产默认24小时）、已有更新的非空封存成果、无未解决问题及补采依赖才回收。每本保留最新可补采成果，回收后旧任务仍显示统计和回收状态，补采使用最新任务或重新同步。采集器只删除不再被其他成果引用的素材副本及原始页面，正式题库、正式图片、教案引用不在清理范围。SQLite空闲页供以后复用，不在运行中做全库VACUUM。回收在采集空闲时执行，重复请求幂等，未确定结果的回收保留状态供重试。

主机低水位或核验/入库积压时，新内容待办保留身份并暂缓，不占采集执行槽。活动采集在安全点封存，分批入库暂缓后保留已提交游标和暂存，资源恢复再处理。后台循环必须在普通进程重启、复用插件 ready 状态时继续运行；安装/迁移的启动单写者标志不代表长期任务调度领导者，运行执行权以数据库约束和租约决定。

### 4.3 增量入库与部分结果

采集数据按页持久保存。稳定封存的不完整快照在通过身份、范围和逐题质量检查后，可以导入合格部分；仍在变化的数据不能假装成稳定快照。

同来源正式写入初期串行，避免跨教材共享题目的更新竞争。正式写入使用有界批次和短事务；一道题本次涉及的内容、目录关系、标签与素材引用一致提交。素材先检查，再让题目进入可用集合。批次进度与结果可靠记录，重复执行不会重复加题。

新增题目插入，正常变化更新，未变化跳过。普通名称修正可自动处理；目录跨教材移动、来源身份冲突、显著批量变化或疑似解析器回归应暂停受影响范围并保留证据。未抓到不等于删除；空答案不覆盖已有可信答案；坏题不覆盖好题；人工禁用及人工题目得到保护。共享题目、标签和素材的处理保留其他教材仍使用的关联。

允许合格批次逐步可用。中途失败保留已提交部分，明确显示部分结果；不承诺整本事务回滚或原子发布。不得将部分增量结果记为旧模型中的完整快照已应用。

### 4.4 补采与定期刷新

2026-10-10 更新：默认从整轮处理结束时计算7天，再发现教材并重新同步全部参与教材；间隔1～365天可配置。失败、部分完成和人工排除是明确处理结果，不要求达到网站全量才结束轮次。采集结束后的核验/入库及暂停待恢复工作仍算未结束；不会叠加两轮。关闭自动更新后当前轮完成即停。手动开始新一轮不必等到日期，执行前仍遵守同教材去重和来源限制。

每轮固定目标、名称、开始/结束时间和结果摘要保存为历史，UTC+8日期用于显示，后台仍以计划ID和轮次关联。提前单独同步一本不改变整轮下次时间，该教材下一轮仍参与。显式补采、瞬时故障的有限重试和入库断点恢复保留；不再给失败教材另排24小时周期或用每本完成日期重置7天计划。

按最新排序的来源会因新题插入发生分页变化，旧页码不保证安全。跨轮补采核对教材/过滤条件/排序、检查新内容并对断点附近有界重叠扫描；无法验证断点时重新扫描相应范围。

增量入库不等于来源只需要增量请求。没有可靠变更游标时，保留周期性范围核对；不能凭第一页不变判断整本未变化。

## 5 异常归属与处理

异常展示归入同步任务，但底层须结构化持久保存，不能只依赖日志尾部或任务的最后一条错误。问题至少能定位来源、教材、任务、目录/页/题/素材、错误类别、证据、尝试次数、下次处理时间和处理结果。

| 分类 | 展示与动作 | 队列影响 |
| --- | --- | --- |
| 正常待补齐 | 如达到本次预算或尚有未扫描范围，登记下一轮 | 继续其他教材，不要求人工确认 |
| 系统重试中 | 临时网络或下载失败，显示重试次数和下次时间 | 有限重试，长等待释放执行位置 |
| 需要人工处理 | 目录无法识别、身份冲突、需要验证等，进入“待处理问题”标签 | 教材局部问题不阻塞其他可执行教材 |
| 来源公共问题 | 频率限制、验证码或来源级访问阻断，显示统一原因 | 暂停同来源，冷却/解除后再调度 |
| 主机公共问题 | 磁盘不足、持续内存压力、数据库不可用 | 暂停受影响工作并保存恢复位置 |

待处理问题支持按教材、错误类型和时间筛选，并能回到任务上下文。问题在任务归档后仍可查；后续任务确实修复对应资源或范围时才自动关闭，记录解决任务和证据。不能因为新任务成功就关闭旧任务全部问题。

来源或主机公共问题保存一份原因与恢复状态，任务引用该原因，不为每本教材生成重复问题。正常补采、自动重试和人工待处理分别统计，避免把所有未抓全任务都列成需要人处理。

## 7 工程边界与同步契约

本节和第 8 节描述目标契约，当前工作区已实现的基础与尚缺增量见[任务清单](实施任务清单.md)。实现时继承已有任务持久化、重启恢复、有限自动续采、快照分页、并发保护及教案快照，逐项改造；不能把这里列出一个目标概念理解为对应代码目前完全不存在。

### 7.1 三端职责和身份

保留 pc / service / collector 结构，优先扩展 bank 和 lesson 插件，不引入第二条采集入库通路。PC 负责交互；Service 负责业务任务、正式 MySQL、权限和教案；Collector 通过独立 HTTP 服务采集，维护自己的 SQLite、原始页、素材和浏览器配置。Service 不直接读取 Collector SQLite，也不执行其本地采集脚本；素材通过受控接口传送到 Service 自己的持久目录。

| 身份 | 含义与持久归属 |
| --- | --- |
| 教材 | 正式教材资料与调度覆盖使用同一身份；来源/学段/学科/来源教材 ID 必须明确 |
| planId | 一个学科范围内的长期计划、预算和启停设置，保存在 Service |
| taskId | 一次单本业务同步，保存采集/检查/入库结果；不能等同于 Collector jobId 或 runId |
| attemptId / jobId | 一次执行尝试与对应远端进程作业；持久记录绑定及所有者，短时恢复不覆盖历史 |
| runId / snapshotDigest | 这次采集成果及固定摘要，作为检查与入库输入；不能用“最新 run”代替已绑定版本 |
| applyId / batchNo | 后台入库工作与批次结果，提交和进度一致；崩溃后可核对并幂等重试 |
| issueId | 跨重跑保留的问题身份与证据；关闭必须有对应修复结果 |

这些是契约中的概念名，不要求每项独立建表。实际字段、索引与迁移由 P0 在现有模型上确定；业务身份和恢复语义不能省略。

### 7.2 数据与接口约束

实现时优先复用现有 job、scope、run 和持久化能力。需要补齐的概念是学科/来源范围、计划、教材调度状态、执行尝试、入库批次、问题记录和公共冷却；是否新增表由迁移设计决定，不预设所有概念都建一张表。

- 来源身份必须稳定且覆盖学科命名空间；教材不能仅按名称匹配，题目不能以内容相似替代来源 ID 去重。
- 同一道来源题可属于多个教材/目录，题目实体和教材关系分别处理，避免删除其他教材的关系。
- 前端只提交服务器认可的教材与来源配置，学科管理不能变成任意脚本、URL 或数据库路径执行入口。
- 采集结果与入库批次均绑定确定的来源、范围和摘要；不一致时停止相关批次，不能忽略异常继续覆盖。
- 派发和提交幂等，避免请求超时后的重试重复执行；跨进程的唯一约束不能仅靠内存变量实现。
- 历史兼容与新流程标识明确，旧的完整快照回退语义不得错误用于新部分增量任务。
- 教案候选列表、计数和配题共用严格条件；教案条目绑定稳定来源题身份及选入快照，同题不能因多个目录关系重复计数。
- 教案修改采用版本校验和请求去重；内容、规则与条目归属一致提交。Word 读取已保存版本，不能混用保存前后内容。
- 新教案页面及接口采用题干白名单，不返回答案、解析和旧教学文字；快照素材参与有效引用保护，不受普通题库清理误删。

### 7.3 同步接口必须提供的行为

| 操作 | 最小契约 |
| --- | --- |
| 创建内容任务 | 新请求只有一个 textbookId；重复请求或同教材活动任务返回已有任务/明确冲突。历史 textbookIds 由旧格式兼容层处理，不能把新请求偷偷转换成多本 |
| 教材发现与自动计划 | 按来源/学段/学科限定；来源地址与脚本只接受服务器登记配置；计划、教材调度、总览读取相同持久事实 |
| 整计划控制 | `POST /bank/sync/plans/{id}/action`：pause/resume/end/start，核对expectedRevision；end携带keepUpdates。只有收尾完成后才转为paused/stopped |
| 教材顺序 | `PUT /bank/sync/plans/{id}/order`提交完整当前教材ID顺序及expectedRevision；清单变更或重复ID拒绝并要求刷新，已派发任务不受影响 |
| 提前单本同步 | `POST /bank/sync/plans/{id}/books/{bookId}/sync`提交expectedRevision、可选listConcurrency和allowPaused；复用现有未结束任务，返回taskId/existing |
| 轮次历史 | `GET /bank/sync/plans/{id}/history`按轮次倒序分页；计划保存controlState/cycleState及cycleFinishedAt/nextCycleAt，持久轮次表保存目标、名称和结果 |
| 提交入库 | 快速返回持久化 applyId 和状态，由后台执行；绑定 taskId、runId、来源范围、快照摘要和契约版本，不在一个 HTTP 请求里等待几万题入库 |
| 读取详情 | 基本状态和已保存摘要保持轻量；目录/问题/批次/日志分页或按需查询；不在首次打开详情时计算全量“是否允许入库” |
| 部分增量 | 明确表示“已稳定封存但未全量覆盖”，与完整快照和运行中可变数据分开；旧接口不能通过伪造 complete=true 获得资格 |
| 重试与恢复 | 请求幂等；先核对远端作业和已提交批次，再恢复。来源冷却、租约和任务执行权需有跨进程保护，过期所有者不能继续提交 |
| 人工处理 | 只对明确问题和范围执行；快照或相关数据版本已变则重新核对，不能用旧页面的选择覆盖新状态 |

复用现有调度器做定时唤醒，合并错过的触发；业务队列、冷却及租约保存于数据库。排队不占执行槽，派发才占执行槽。不能把创建大量 queued 记录等同于它们都获得 active_slot。

待办最早派发时间用数据库 UTC 时钟比较，接口返回带时区时间，避免 Service、Collector 与教师浏览器的时区差异改变冷却。人工解除来源暂停必须校验当前状态版本，不能覆盖较新的阻断，也不能缩短尚未结束的 Retry-After；解除暂停与对已封存任务发起续采是两个操作。采集器健康与来源可执行状态分别表达，健康成功不能绕过公共暂停。

日志和问题摘要在业务侧可靠保存后，再按策略清理远端终态 job。当前状态、最后错误和日志尾部不能代替完整问题记录；进入终态不能用空缓冲覆盖已经保存的日志。

| 后续明确 | 题干直接修改、Word/PDF 材料解析、外来题入库、跨教材组题、作业单独导出、更多纸张模板 |

“实施默认”是本方案用于落地的选择，不等于用户逐项确认，也不要求先追加一轮问答才能继续设计。复杂材料导入保留需求，首版不依赖 AI；课型可作为分类信息，不强制填写教学目标、学情和分钟安排。

本模块与同步代码一起交付，P5 实际教材覆盖不阻塞实现及合成数据验证。实际选题仍需对应教材有合格题目；真实教师试用由用户部署后验收。

### 8.2 页面与操作流程

#### 8.2.1 一个编辑器，两种入口

顶部显示教案名称、教材、保存状态、预览及导出。左侧为教学内容列表和待整理区；中间为当前内容的条件或题库筛选器；右侧为已选题目及顺序。窄屏改为分区切换，不强行挤成三栏。

- 按教学内容配题：新增内容 → 选择目录范围 → 添加一组或多组条件 → 看候选或补齐 → 调整顺序。
- 直接选题：设置范围与条件 → 浏览候选 → 选入内容或待整理 → 再分组、排序。

两种入口使用相同草稿 ID 和条目集合，切换只改变当前操作面板。候选中显示“已选入”和所在内容；改筛选条件不清空已经保存的题目。

#### 8.2.2 多组条件示例

| 教学内容 | 条件组 | 目标题数 | 一次选题的约束 |
| --- | --- | --- | --- |
| 同号相加 | A：基础＋填空 | 2 | 所选知识点、基础难度、填空题同时满足 |
| 同号相加 | B：提升＋解答 | 1 | 所选知识点、提升难度、解答题同时满足 |
| 异号相加 | C：基础＋选择 | 2 | 范围按该内容的目录配置，不继承上一内容 |

内容保存目录范围；各条件组继承这个范围，分别设置题型、难度、数量和高级条件。首版不增加多层条件覆盖：同一内容需要不同目录范围时拆成两个内容。规则名称可自动生成，也可由老师修改；规则顺序与题目展示顺序相互独立。

#### 8.2.3 不能含糊的操作语义

| 操作 | 服务端和页面应保持的结果 |
| --- | --- |
| 查看候选 | 显示符合条件总数、排除本份教案已选题后的数量；按整题去重 |
| 在规则内手动选入 | 归属该规则，通过其硬条件才计入名额；不符合的题可作为手选题保留，需明确选择该操作 |
| 在题库中直接选入 | 可指定内容，默认作为无规则的手选题；可以后续指定到符合条件的规则 |
| 补齐当前内容/全部内容 | 仅填补规则缺额，保留已有条目、归属与位置；新题追加到对应内容末尾 |
| 改条件或减少数量 | 原题保留；不匹配的标注待复核，超出目标的标注超额，不自动删题或转移归属 |
| 换一题 | 在原位置替换；规则题遵守当前规则，手选题使用老师明确选择的条件；没有候选时原题不变 |
| 移动题目 | 修改教案归属和顺序；跨内容默认解除原规则归属，允许指定目标规则并重新核对 |
| 删除规则 | 题目保留在原内容，转为手选题；不能连带删除 |
| 删除内容 | 其中的题目移到待整理，解除规则归属；不能连带丢失 |
| 移出与撤销 | 只影响这份教案；短期撤销恢复服务器保存的原条目快照，遇到已选同题不重复恢复 |
| 更换教材 | 首版新建另一份草稿；旧草稿保留，不把原教材题目静默放到新教材范围 |

候选分页勾选保存明确的题目 ID。筛选变化可以清空临时勾选并提示，但不能清空已选入的题目。首版不提供含义不明确的“全选全部匹配题目”；按数量选入有明确上限。

### 8.3 筛选计数与补齐

#### 8.3.1 一份筛选契约

后端定义统一的 QuestionFilter，供候选列表、计数、补齐、手选校验和换题共用。字段包括教材及目录范围、题型集合、难度标签或易度区间、年份范围、省市、考试类型、附带知识点数量、小问上限、是否允许图片和表格。数量目标单独保存，不混入过滤条件。

不同维度按 AND，同维度多选默认按 OR。空集合表示不限，不能与“一个也不允许”混用。难度分级与易度区间在请求中二选一，使用经过核对的来源映射；来源易度通常数值越大越容易，未知系数不能凭估算满足数值区间。

服务端检查学科、教材、目录的真实归属与可用状态。选章节时包含本节点及其下级目录的有效关系，不能只找叶子知识点而漏掉直接挂在章节上的题；同题命中多个目录仍只算一次。

目录命中与知识点证据分开：query_membership 表示来源目录查询命中，provider_asserted 表示来源明确标注。候选可以显示两者的区别；“最多附带知识点”只统计来源明确标注的已知知识点，不把所有目录命中当成知识标签，也不承诺已经识别题目的全部知识。

启用某项硬限制时，相关字段未知的题不当作符合条件。例如年份未知不通过年份限定，小问未知不当成 0，没有可用知识标签依据时不能保证附带知识点为 0。不限时仍可以出现这些题，编辑页标注未知。

#### 8.3.2 题干和素材的可用性

查询只使用正式库中启用且题干可用的题目。题干引用的必要素材要就绪；判断图片、表格及素材完整性时只看题干使用的内容，不能因为答案图片缺失就排除一道完整的题。

复用题库自动检查结果，补充按 question_id、content_hash 维护的轻量检索事实：题干检查状态、是否含图片/表格、必要素材是否就绪和检查时间。缺少合适承载位置时增加一张派生表，不另建搜索服务。历史记录先有界回填，题目或素材变化使相关结果失效并重算；未知不能伪装成已经检查合格。

计数和列表使用相同的可用性谓词，不在每次筛选时逐个打开全库图片。选入、换题及导出前核对实际素材；发现文件已丢失时更新检查结果、明确指出受影响题并刷新数量，不悄悄输出空图或用其他题替代。

#### 8.3.3 数量口径与归属

每个条目最多归属一个内容下的一条规则，也可以没有规则。即使同时满足两条规则，同一道题也只能占一个名额；归属以保存的 ruleKey 为准，不因条件变化自动挪到另一条规则。

对每条规则，缺额＝max(0，目标题数－归属该规则且满足当前条件的已选题数)。保留但不符合新条件的题、未分配到规则的手选题、待整理题目，都不自动抵扣规则缺额。页面分别显示符合数量、待复核数量和手选数量，避免把“已经选了 3 道”误当成“三个条件都满足”。

归属规则的已选题按保存时的题目属性快照核对；来源更新不静默改变已有题干或元数据。来源后续停用等当前状态单独提示，禁止继续自动选入，不借此覆盖或删除已有教案内容。

#### 8.3.4 多规则共同配题

补齐先读取草稿版本和该版本的已选题集合，排除全部已选题，再给本次待补规则共同分配候选。先处理候选较少的规则，并使用有界的重新分配寻找可行组合；已经保存的题不参加重新分配，查询期间不持有草稿写锁。

例如 A 可选 Q1、Q2，B 只能选 Q1，各需 1 道时，应给 A 选 Q2、B 选 Q1，不能先把 Q1 给 A 再声称 B 无题。

实现采用小规模二分匹配：规则容量为缺额，题目容量为 1；不足时优先填补更多名额，平局按规则顺序和稳定排序决定。无需外部求解器或任务平台。排序偏好只在符合硬条件的候选中发挥作用，不使用现有自动放宽等级。

为避免全量候选驻留内存，设本次总缺额为 D，每条规则最多取 D 个不同的合格题 ID；候选不足 D 时取全。只要这 D 个候选都确实满足规则并已排除现有题，该上限不会仅因截断而破坏原本可满足的名额分配：含有一个满 D 候选池的规则子集，其可选集合已不小于本次总名额。不能改成每条任意只取 10 道再宣称题库不足。

匹配只加载 ID 和必要属性，选定后再取完整题干与快照。若复核发现候选失效，则继续分页补候选并重算；达到执行预算时明确返回“本次计算未完成”，不当作“题库只有这些题”，也不留下半个未说明的草稿变更。

#### 8.3.5 性能与一致性

首版建议候选每页 20 道、最多 100 道；沿用单规则最多 20 道、整份最多 40 条规则，再增加整份已选题及规则目标总数各不超过 200 的保护上限。以上为可配置建议值，不是已上线配置；历史超过上限的教案仍可读取，不截断记录。

修改条件后，保留的不匹配题仍占草稿容量；手选题也计入容量。已选数加本次待补数超过上限时，提前提示整理题目或缩小本次补齐范围，不删除原题、不截断后假装已补齐，也不将容量限制归因于题库缺题。纯内容分组也设置有界数量，防止用空内容绕过规则数限制。

列表使用稳定排序和分页，通过 EXISTS 或去重子查询处理多目录关系。总数与当前页在同一次一致性读取中计算；不同次请求间题库可能更新，返回查询时间，提交选题时再次校验。超时不返回伪造的 0。

前端主动搜索或短防抖后查询，忽略旧请求响应；条件变化才刷新候选，不因草稿排序重算全库。缓存如有使用，必须同时考虑规范化条件、题库数据变化和草稿 revision，不能缓存一份所有草稿通用的“剩余数”。

用接近历史任务量级（约 5 万道题）的测试数据检查 SQL 执行计划、响应时间、内存和导出耗时，结合实际过滤组合补索引。初始验收目标为常用筛选 p95 不超过 2 秒、20 道内补齐 p95 不超过 5 秒；这是待测试目标，最大规模单独记录，不能靠统一提高 10 秒超时掩盖全量加载问题。

### 8.4 草稿模型与历史兼容

首版继续使用现有四张教案表，通过独立迁移增加新编辑格式。内容和规则规模有限，先存一份有版本的编辑 JSON，不为每个界面概念新增表；题目条目仍单独存储，保留数据库去重约束。

| 存储 | 调整方案与唯一事实来源 |
| --- | --- |
| lp_scheme | 保留；新草稿创建专属方案行，textbook_id 为不可变范围，不与其他草稿共用可修改配置；旧字段保持兼容默认 |
| lp_pick_rule | 保留旧教案规则；新格式规则只在 editor_json 中维护，不双写两套可修改规则 |
| lp_generation | 增加 editor_schema_version、revision、editor_json 及可空的 source_generation_id；新草稿使用版本 2，旧记录为版本 1。editor_json 存标题、内容、规则、导出设置；source_generation_id 记录复制来源；lesson_json 和旧规则快照继续保存原数据 |
| lp_generation_item | 增加 group_key、rule_key；rule_id、phase 对新格式允许空，旧记录原值保留；sort_no 表示内容内顺序；沿用题目快照和同教案同题唯一约束 |
| lp_editor_operation（新增） | 记录请求 ID、操作者、对象、请求摘要和提交结果，与草稿修改同事务提交；用于超时重试去重和短期移出撤销，不建设无限历史版本系统 |

editor_json 包含有序 groups，每个内容有稳定 groupKey、名称、catalogIds 和有序 rules；每条规则有稳定 ruleKey、targetCount、filter。内容允许先只命名，但保存可执行规则前必须确定教材内目录范围；无规则的分组可以仅用于整理手选题。数组位置是内容和规则顺序的事实来源。题目位置只看条目的 group_key、sort_no、item_id，不按 rule_id 排序。

group_key 为空表示待整理，rule_key 为空表示手选；有 rule_key 时必须能在同一草稿的对应内容找到。服务端统一校验并在一次事务中处理内容删除、规则删除和相关条目归属，避免孤立引用。摘要中的数量为派生结果，不另存一份可人工修改的计数。

保存状态和配题状态分开：请求成功保存不意味着所有规则已满足。新格式不把旧 ready/partial 状态同时用作草稿保存状态和题库覆盖结论；列表通过格式适配器显示“已保存、缺 N 题、待整理 N 题”等实际信息。

#### 8.4.1 快照与素材保留

选入时由服务器生成题干、筛选属性、目录证据和必要素材快照，记录来源题 ID、内容摘要及检查版本；不接受客户端上传的任意题干作为可信题库题。新教案题目 DTO 和新快照只包含此流程需要的字段，不返回答案或解析。

沿用已有快照机制，但补齐素材保留：题目快照不能只引用可能被下一轮覆盖的路径。优先使用按文件摘要标识的不可变素材及教案引用；无法保证原存储不可变时，选入前复制到教案快照素材区。先准备文件，再以短事务提交引用；临时文件延迟回收，不能在数据库事务里下载网络图片。

清理策略计入仍在使用的教案、导出中的快照以及可撤销操作的有效引用；与实施清单 C14 对齐。导出完成前持有素材引用，删除草稿不能使正在生成的文件中途丢图。题库更新后旧教案仍使用选入时内容，首版不自动刷新旧题。

#### 8.4.2 历史兼容

新增独立编号迁移，声明在插件迁移清单中，不修改已执行的 001、002。先验证数据库升级、旧数据读取与恢复，再启用新页面；保存新格式后，回退旧应用前必须禁用新写入并使用兼容版本，不能默认旧代码理解新空字段。

旧教案通过只读适配展示：原教学阶段转换为展示分组，题干快照优先；新页面和题目版导出忽略旧教学文字及答案，但原库内容保留。需要编辑时“复制为可编辑教案”，分配新 ID，并保存来源记录关系；旧记录不被改写。

对缺少快照的早期记录明确标注“历史快照缺失”。复制时可以依据当前题库建立新快照并记录复制时间，不能声称恢复了当年的题干；题目或素材已不存在时显示具体缺项。旧重新生成、文字保存等接口在过渡期只处理旧格式，拒绝修改版本 2；新页面只走新编辑接口。

### 8.5 教案接口与并发约定

沿用 /lesson/plan 前缀、当前鉴权和权限码。下表是拟定契约，最终命名可以调整，但操作语义必须保留。

| 接口 | 作用及关键输入/输出 |
| --- | --- |
| GET /options、/versions、/textbooks、/catalog-tree | 沿用并适配学科与真实题型/地区字典；返回范围内可用选项 |
| GET /generation/list | 复用历史列表，区分旧结果和新草稿，提供继续编辑或复制入口 |
| POST /drafts | 创建空草稿；教材、标题、请求 ID；返回草稿 ID、revision、导出默认设置 |
| GET /drafts/{id} | 读取结构、条目快照、规则达成情况和待整理数；不执行全库抽题或重型素材扫描 |
| POST /candidates/query | 传草稿、规则或临时 filter、分页信息；返回题干候选、匹配总数、未选数、规范化条件和查询时间 |
| POST /drafts/{id}/commands | 处理明确类型的编辑命令：改标题/导出设置、增改删内容或规则、按明确题 ID 选入、指定规则归属、移动、排序、移出和撤销；不接受任意字段透传更新 |
| POST /drafts/{id}/pick | 题库直选中的“按数量选入”：临时 filter、数量、可空的目标内容；共用严格选题与去重，作为无规则条目保存，不自动创建永久条件组 |
| POST /drafts/{id}/fill | 指定规则/内容或全部规则，读取服务器保存的条件与缺额，返回新增条目和逐规则结果 |
| POST /drafts/{id}/items/{itemId}/replace | 替换单条；规则题使用保存的条件，手选题要求明确 filter；返回替换结果或无候选原因 |
| POST /drafts/{id}/export | 指定 revision，读取已保存打印设置和快照，生成题目版 Word |
| DELETE /drafts/{id} | 使用版本和请求 ID 删除可访问的新草稿，按引用关系延迟回收素材；旧历史删除入口只处理旧格式 |
| POST /generation/{id}/copy-as-draft | 把旧结果或新草稿复制成独立可编辑草稿，不修改来源 |

编辑请求包含 expectedRevision 和 requestId；创建及复制也有 requestId。先鉴权，再检查同一操作者的幂等记录；同键同请求返回原提交结果，同键不同请求拒绝。所有改动和幂等结果在同一事务提交，网络丢响应后重试不能又选一批题或再次换题。

去重标识、对象和请求摘要保留到草稿生命周期结束后的重试保护期，创建请求不能因短期撤销缓存过期再次创建草稿；大体积撤销快照可以单独按短期策略回收。过期操作只返回已处理或已过期，不重新执行旧的随机换题。具体保留时长纳入 实施清单 C14 的配置与测试。

昂贵查询、素材准备不持有草稿写锁。提交时短事务校验 revision 并再次检查选中题目的内容摘要、状态和唯一约束；发生并发修改返回冲突，保留本地待提交内容并提示刷新，不覆盖另一窗口结果。超过执行预算而未完成分配时不提交本次 fill，重试仍针对明确版本。

批量手选返回新增、已存在、条件不符或已失效的明确结果。已失效条目不加入，成功条目与结果记录原子提交；前端据此刷新，不把部分成功提示为全部选入。新规则编辑和移动等一次命令不能留下半套结构。

按数量选入与按规则补齐复用同一匹配器，区别只在于前者使用本次临时条件和数量，后者使用保存的规则与缺额。前者首版每次至多 20 道，整体仍受草稿容量限制；数量不足返回实际选入数和缺口，超时未完成则不提交。明确进入规则面板后再选题时，使用该规则归属，不同时维护两套结果。

权限沿用 lesson:plan:list/generate/export/remove 的业务边界，各对象操作仍须核对可访问范围；不能只检查用户有菜单权限。新草稿默认归创建者维护，已有被授权的管理员按既有管理范围处理，暂不增加协作共享产品；历史记录沿用现行访问策略。候选查询、素材、详情、导出使用一致的范围校验，不因新路由绕过题库限制。

素材请求必须证明题目和素材属于可访问草稿快照或本次允许查询的题库范围。所有内容渲染继续做 HTML 清理，导出仅使用受控素材路径，不把来源 HTML 当成任意脚本或外部文件指令。

### 8.6 前端保存与预览

保留 plan 页面作为入口，拆出教材范围选择、内容列表、条件组编辑、公共筛选器、候选列表、已选题列表和打印预览。候选与已选题复用题干渲染组件；公共筛选器共用字段解释，避免题库直选和规则配题出现两套难度逻辑。

一个草稿状态模块管理服务端 revision、内容、条目、选中面板和待提交操作。输入标题或条件可短防抖保存；增删、选入、移动、换题等离散操作明确提交，保存请求按顺序执行。显示“保存中/已保存/保存失败”，请求失败时保留输入并允许重试，页面关闭前只提醒确有未保存的变更。

预览和导出先等待当前保存完成；保存失败不悄悄导出旧内容。预览读取确定 revision 的题目顺序和打印设置，Word 请求必须指向同一 revision。导出开始时读取一致快照并脱离写事务处理，之后的编辑不改变这次导出；若读取前版本已变则返回冲突，重新预览。

排序提供上下移动和移动到内容的控件，拖动作为可选增强。移出撤销使用服务器保存的操作前快照和有效请求记录，限制为短期最近操作；过期明确提示，不以当前题库内容冒充原快照，也不引入复杂时间线。

### 8.7 Word 导出

Word 与网页预览共用一份打印模型：标题、按顺序的内容标题、连续题号、题干、必要素材、留白。待整理题追加到补充题区，所有已选条目恰好输出一次。没有答案、解析、教学文字、来源附录或“请补充答案”提示；来源和难度仍可在选题界面查看。

首版先提供分组标题开关和统一题后留白，建议 0/2/4 行三档；不增加大量样式参数。文字和支持的表格保持可编辑，公式与几何图按实际来源格式分别处理：已有公式图片需清晰嵌入；文字、上下标和支持的数学结构保留语义。不能把图片公式宣称为 Word 原生可编辑公式。

选取包含分数、根式、上下标、几何图、表格、长题干和多小问的真实题建立导出样例。实际生成 DOCX，渲染后逐页检查丢字、裁切、乱码、空图、跨页和留白，再人工用 Word 或 WPS 抽查编辑效果。网页与 Word 要求题目和顺序一致，不承诺浏览器与排版软件的页码完全相同。

必要素材缺失或内容无法正确渲染时返回具体题目和原因，不下载一份看似成功但内容不完整的文件。受控数量下先复用现有导出方式并避免阻塞异步请求处理；若真实测量仍超预算，再增加后台导出作业，首版不预先搭一套通用任务系统。

### 2026-10-11 教材任务与执行历史

- 一个轮次内，每本教材是一条逻辑任务。点击“再同步一次”或“补采”创建独立执行记录，列表仍只展示该任务的最新执行。下一轮定期同步建立新任务，不跨轮次合并。
- 执行记录保留原有 run_id、scope、Collector 快照、日志、核验与入库绑定；logical_task_id 只负责归组。既有明确 retry_of_run_id 关联由迁移 026 回填，未关联的历史任务不按名称猜测合并。
- 学科计划“再同步一次”沿用当前轮次该教材的任务；排队或运行中再次点击返回已有执行。同一教材的入库尚未结束时继续展示已有执行。
- 列表显示最新状态、实际启动次数、最近启动时间；排队取消保留记录但不计入实际启动次数。“继续入库”不新增采集执行、不增加执行次数。
- 任务列表、学科计划、任务详情均提供执行历史入口，每条执行可打开原有详情、成果、入库结果与日志。按状态筛选以最新执行为准。删除任务同时删除它的全部执行记录；任何执行仍活跃或存在未完成入库时整个删除回滚，正式题库与 Collector 快照不因此删除。


### 2026-10-11 来源验证人工浏览器（第一版）

同步计划告警入口“打开浏览器处理”连接服务器同一 Chrome 档案。系统通过登录权限 bank:sync:control 创建操作人独占会话，短期一次性票据连接 WebSocket/noVNC；x11vnc 仅监听采集容器回环，不对公网开放端口。采集与接管互斥，断线 90 秒或会话 30 分钟到期关闭浏览器，来源仍暂停。

第一版支持带具体目录和页码的题目列表验证（包含旧任务 13 的封存数据）：在同一浏览器重试原目录/页的 POST，必须 HTTP 200、合法题目结构和非空题号才可继续；检查间隔至少 10 秒，有 Retry-After 时保留冷却。检查成功两分钟内“补采并恢复队列”，先创建同一逻辑任务下的优先补采执行，再关闭人工浏览器并解除来源暂停。取消、失败或断线均不恢复来源。直接“已完成验证”旧接口不能再跳过实际核验。教材发现/无具体页码的其他阻断暂不由该入口自动核验。
