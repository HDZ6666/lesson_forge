## 接手时先完成这些动作

1. 读取仓库适用的 AGENTS.md 和这三份主文档。公共边界看规格第 1、2、7、9 节；同步开发重点看第 3～5 节，教案开发重点看第 8 节。
2. 查看任务清单第 2 节的当前源码基础、第 4～5 节的逐项差距及第 6 节的本轮验证，再检查 git status、当前分支、实际文件和已有测试；工作区包含此前未提交修复，先按清单 P0 建立可重现基线和隔离环境。
3. 根据当前用户要求与清单首个依赖已满足的任务执行，简短说明选择后直接检查和实现；不重复询问已经确认的产品需求，不从历史“下一步”启动另一套方案。
4. 按规格中的 A01～A20 运行与改动相应的验证，将结果、环境、提交/基线、剩余问题和下一项写回任务清单。没有做的验证如实记录。

只有缺少会改变业务结果的信息时才提出具体问题；实现方式和可配置默认值可以依据规格与代码决定。发现某功能已经存在时优先复用和验收，不能因为任务未勾选就重写。

## 有冲突时怎样判断

- 用户在当前会话中的明确要求优先；变更已确认需求时记录到规格。
- “应该怎样工作”以实施规格为准；“现在实际怎样工作”以当前代码和对应环境的新验证为准；“已完成哪些任务”以任务清单证据为准。
- [archive](archive/README.md) 只保留旧设计、旧进度与故障证据。其“当前”“已部署”“下一步”等措辞都指当时，不作为新需求或新环境状态。
- 插件 README、运行说明解释已有入口，不覆盖新规格。原型使用演示数据，不代表真实题库、接口或 Word 功能已经实现；旧原型中的答案和教学指导不在本版范围。
- 本文提供工作上下文，不授予额外生产操作权限。按当前会话已授权的范围执行，隔离环境不得因复用配置而写生产。
