# 题库同步脚本说明

更新时间：2026-09-07。当前功能状态见 [采集端进度](进度/采集端进度.md)，真实故障见 [实际问题](采集端实际问题.md)。

## 1. 当前入口

| 入口 | 用途 |
| --- | --- |
| collector/server.cjs | 独立 HTTP 服务、受控任务编排 |
| collector/zujuan_metadata_sync.cjs | 版本与教材发现 |
| collector/zujuan_question_sync.cjs | 当前 HTTP 内容任务的列表 API 采集器 |
| collector/legacy/zujuan_sync.cjs | 旧页面采集器，仅人工/定时使用（`npm run legacy:sync*`），参数和默认值不可与新入口混用 |
| collector/qbpkg.cjs | 离线包 build/verify |
| service/plugins/bank/publisher/cli.py | MySQL 离线发布工具 |

根目录三个 `.cjs` 只是入口与兼容导出，实现按职责放在 `collector/src/`（`shared / sources/zujuan / policies / assets / storage / jobs / api / cli`），结构见 [collector/README.md](../collector/README.md)。

新入口使用公开页面建立匿名会话、读取静态目录 JSON、请求题目列表 API，不要求用户登录。CLI 默认有头；HTTP 任务由部署侧 COLLECTOR_HEADFUL 决定，但该变量为 false 时 server 不会向新入口传 `--headless`，生产容器内容任务实际是有头 Chrome 跑在 Xvfb 上。现有代码仍有人工等待/会话切换逻辑，无人值守冷却恢复属于待实现计划。

## 2. 本地服务配置

需要 Node >=22.5、Chrome，以及工程依赖。以下是运行说明，本次整理未执行这些命令。

~~~bash
cd collector
npm ci
npm start
~~~

Service 设置：

~~~text
BANK_COLLECTOR_URL=http://127.0.0.1:9110
~~~

默认 Collector 监听 loopback、不启用 token。非 loopback 绑定必须设置 COLLECTOR_API_TOKEN，Service 使用匹配的 BANK_COLLECTOR_TOKEN。token 是自建服务的鉴权，不是组卷网登录。

| 配置 | 用途 |
| --- | --- |
| COLLECTOR_API_HOST / COLLECTOR_API_PORT | 默认 127.0.0.1:9110 |
| COLLECTOR_DB | 默认 collector/data/zujuan.sqlite3 |
| COLLECTOR_DATA_DIR | 原始响应与素材，默认 collector/data/zujuan |
| COLLECTOR_PROFILE_DIR | 默认 collector/.cache/zujuan-sync-profile |
| COLLECTOR_HEADFUL | 服务子进程是否显示浏览器，由部署配置控制 |
| COLLECTOR_NODE_BIN | 采集子进程 Node 可执行文件 |
| COLLECTOR_JOB_TIMEOUT_MS | 单任务总时限，默认 24 小时，到期终止子进程并记 `errorCode=job_timeout` |
| COLLECTOR_STALL_TIMEOUT_MS | 停滞判定，默认 20 分钟；无事件无日志即终止并记 `errorCode=stalled`，人工验证等待不计入 |
| COLLECTOR_EVENT_CHANNEL | 子进程事件通道 `ipc`（默认）/`stdout`/`none` |
| COLLECTOR_LIST_CONCURRENCY / COLLECTOR_ASSET_CONCURRENCY / COLLECTOR_DELAY_MIN_MS / COLLECTOR_DELAY_MAX_MS | 采集节奏（列表窗口并发、素材预取并发、窗口间隔），不设则用 CLI 默认 8 / 8 / 2500–4000；实测数据与建议见 collector/README.md |
| BANK_COLLECTOR_URL / BANK_COLLECTOR_TOKEN | 后端到 Collector 的连接 |
| BANK_COLLECTOR_TIMEOUT_SECONDS | 后端单次请求超时 |
| BANK_ASSET_ROOT | 后端自己的素材存储根目录 |

Collector 自持 data 和 profile；Service 不共享 SQLite，不读取 Collector 宿主路径。素材通过 HTTP 按摘要下载到后端自己的持久目录。

## 3. 新题目入口的手动运行

~~~bash
cd collector
npm run sync:zujuan:questions -- --help
npm run sync:zujuan:questions -- --textbook-id 260617
~~~

第二条会实际发起采集，默认下载素材。不要在服务任务已占用同一个数据库/profile 时并行运行。

隔离的小范围采集示例：

~~~bash
npm run sync:zujuan:questions -- --textbook-id 260617 \
  --max-catalogs 1 --max-pages 1 \
  --db data/manual-probe.sqlite3 --data-dir data/manual-probe
~~~

限页/限目录运行未达到全量完整条件时会保留不完整状态，不应将其解释为全册采集失败或成功。测试结束必须结合错误记录判断。

可选 --cdp-url http://127.0.0.1:9222 用于调试已有 Chrome；新入口只管理自己创建的采集标签，不关闭用户浏览器。日常运行无需人为先打开浏览器，该参数也不是无人值守方案。

## 4. 新建、重试与续采

- 网页新建任务：新 task、新 job，每本教材新 run。
- 网页重试任务：新业务任务，重新采集；不是续采。
- 网页断点续采：保持业务 task，新 job/run，继承旧运行已保存的快照与断点。
- CLI 的 --resume-run-id 指定可恢复的旧运行；范围必须匹配，完整封存的成功快照不能作为不完整续采源。具体允许参数以新入口 --help 为准。
- 后端重启后恢复远端轮询：不新建采集运行。
- 当前没有完成持久化“到时间自动重新执行”的闭环；不能把页面刷新、轮询或短时间重试当作定时续采。

## 5. API 边界

主要接口：

~~~text
GET  /health
GET  /v1/health
POST /v1/jobs
GET  /v1/jobs/{jobId}
POST /v1/jobs/{jobId}/cancel
GET  /v1/metadata/snapshot
GET  /v1/runs/{runId}/catalogs
GET  /v1/runs/{runId}/questions
GET  /v1/runs/{runId}/questions/{externalId}
GET  /v1/runs/{runId}/snapshot-page
GET  /v1/runs/{runId}/assets/{sha256}
~~~

/health 为无敏感信息存活检查，受控 /v1 接口按配置鉴权。任务只接收受控类型和教材范围，不接受 SQL、脚本路径、数据库路径或任意命令。快照页需校验运行、教材、集合、游标和大小。

任务状态来自子进程的结构化事件（IPC），不再解析日志文本：`GET /v1/jobs/{jobId}` 在子进程创建 run 后即返回 `collectorRunId`，终态带 `errorCode`（如 `verification_required`、`stalled`、`job_timeout`、`collector_restarted`）与结构化 `errorMessage`。任务持久化在 `collector_jobs` 表：同一 SQLite 上只能有一个活动任务（跨进程 409），API 重启后历史任务仍可查询，遗留活动任务被封存为 `interrupted`/`failed`。

## 6. 采集数据及字段原则

- 题目按来源/外部 ID 保留稳定身份，同题跨目录保留多对多关系。
- 目录层级采用显示嵌套关系，来源原始 parentId 作为证据保留，不能混作教材显示父节点。
- 普通知识目录与知识点请求分别映射 categoryId、catelogTokpointId；隐藏筛选默认“全部”，避免静默缩小范围。
- 保存题干、完整题型、难度及系数、来源、引用信息、知识点/能力标签、图片/公式引用及原始 gzip。
- qdid/qyid 不是系统字典主键或排序号；正式字段必须经过已有字典规范化，原始代码留存。
- 题目出现于某查询结果，不等于来源声明该题的固有标签，保留查询证据与来源声明区别。
- 基础同步不额外执行全量筛选归属扫描；答案与解析标记 not_collected，不伪造 detailFetched。
- 来源 total、唯一题数、出现次数、扫描进度分开；失败素材/页记录不应丢弃其他成功页。

## 7. 正式入库与离线发布

当前有两条正式写入实现，采集完成本身不触发正式覆盖：

1. Service 任务应用：读取绑定快照、校验完整性/范围/并发状态、传输并核验素材，再事务性写正式表。
2. qbpkg/Publisher：离线包校验、影子表装载、二次校验、数据集切换与回退。

离线工具参考：

~~~bash
cd collector
node qbpkg.cjs --help

cd ../service
python -m plugins.bank.publisher.cli --help
~~~

Publisher 提供 verify、register、process、publish、rollback、recover、run-pending、cleanup。数据库参数使用 BANK_MYSQL_*，素材使用 BANK_ASSET_ROOT。管理端的发布请求需要消费者实际执行；生产是否部署了外部消费者须另行核实。

包内有 manifest.json、snapshot.sqlite3、diff-report.json、validation.json、checksums.sha256 及必要素材。七张业务影子表和 qb_dataset_meta 参与原子切换，qb_sync_batch 保留审计。字段与格式详见 [发布包历史设计](计划2-题库后端前端实现.md)，实际兼容性以当前工具为准。

不要复制旧说明中的完整范围声明来给部分数据强行打完整标记，也不要用工具构建成功代替真实覆盖验收。

## 8. 排障与验证

先根据 taskId/jobId/runId 定位当前运行，再查看具体目录、页结果、原始错误与快照完整性。SQLite ExperimentalWarning、浏览器最小化警告不是采集失败的直接证据；CLI 最后一行帮助文字也不是原始错误。

后续验证按采集端进度清单执行；npm test 是离线测试入口，不代表生产整册成功。每次真实故障更新实际问题台账，记录版本、环境与解决证据。
