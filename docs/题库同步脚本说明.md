# 题库同步脚本说明

> 本文区分采集器、版本/教材元数据发现、离线 qbpkg 工具和独立 MySQL Publisher；生产调度和全量数据尚未部署。

## 1. 当前定位

`collector/zujuan_sync.cjs` 是独立 Node/Playwright 题目采集器，`collector/zujuan_metadata_sync.cjs` 是同一工程里的版本/教材发现入口。二者都不是 FastAPI 模块或 MySQL 写入器。它们可由命令行独立运行，也可由 `collector/server.cjs` 以受控子进程编排；FastAPI 只通过认证的 collector HTTP API 提交固定任务和读取有界快照，不共享 SQLite，也不传递脚本路径、SQL 或任意命令。脚本使用真实 Chrome 访问公开题库页面，将结果写入 collector SQLite；默认不下载素材内容，也不生成 `.qbpkg`。

当前代码固定来源提供商为 `zujuan`，允许的页面/素材域名和防护页熔断逻辑写在脚本中。脚本不破解验证码、不绕过登录、不主动读取受限答案；收到 401/403、验证码、JS 挑战或页面结构契约变化会停止。

## 2. 已实现能力

### 2.1 管理端同步中心

题库插件只有一个“同步中心”入口。操作者确认来源规则和授权范围后，按两个阶段主动操作：

1. 点击“刷新版本与教材”，创建一个元数据任务，发现本次来源中的全部版本和教材；
2. 在版本分组下通过左右穿梭框选择教材，再点击“同步所选教材内容”，创建一个内容任务。

两阶段的接口和执行边界如下：

```text
POST /bank/sync/run/metadata/start
  -> zujuan_metadata_sync.cjs（发现本次全部版本和教材）

POST /bank/sync/run/content/start
  -> 校验 metadataRunId + 用户选择的 textbookExternalIds
  -> 一个内容任务，内部按选择顺序调用
     zujuan_sync.cjs --textbook-id ... --all-catalogs
     （每本教材的 1/2/3 级目录和题目在同一任务中完成）
```

不会自动为每本教材创建任务，也不会在刷新元数据后自动开始内容采集。目录和题目属于同一个内容任务，用户只需在教材层面选择范围；内容任务结果仍只写 collector SQLite，不会自动合并到 MySQL 正式题库。

前端通过 `/bank/sync/run/current` 和 `/bank/sync/run/{run_id}` 轮询状态、进度及有限日志，也可调用 `/bank/sync/run/{run_id}/cancel` 停止。内容任务绑定明确的 `metadataRunId`，只处理该快照中明确发现、具备稳定教材 ID 和入口章节的教材，不会静默复用后续元数据运行。

### 2.2 运行参数

在 `collector/` 目录安装依赖后，以下命令当前可执行：

```bash
cd collector
npm install
npm test
npm run sync:zujuan:metadata -- --acknowledge-source-policy --headful
npm run sync:zujuan:metadata -- --status
npm run sync:zujuan -- --acknowledge-source-policy --chapter-id 261314 --max-pages 1 --limit 1 --headful
npm run sync:zujuan -- --status
```

脚本要求 Node.js `>=22.5.0`、本机 Google Chrome 和已确认的来源授权范围。默认路径：

```text
data/zujuan.sqlite3
data/zujuan/raw/
data/zujuan/assets/       # 仅使用 --download-assets 时出现
.cache/zujuan-sync-profile/
```

实际支持的选项包括：

- 目录：`--chapter-id`、`--textbook-id`、`--catalog-id`、`--catalog-level`、`--all-catalogs`、`--within-chapter`。
- 分页：`--start-page`、`--max-pages`、`--limit`、`--no-resume`。
- 过滤：`--scene`、`--question-type`、`--difficulty`、`--category`、`--year`、`--fresh`、`--sort`。
- 采集：`--list-only`、`--refresh-details`、`--download-assets`、`--no-save-raw`、`--include-visible-solutions`。
- 运行：`--headful`、`--delay-min`、`--delay-max`、`--timeout`、`--db`、`--data-dir`、`--profile-dir`、`--status`。

单独传入 `--textbook-id` 且没有 `--chapter-id` 时，题目同步器从 `source_textbooks.bootstrap_chapter_external_id` 解析入口章节，生成 `zj{章节ID}` URL；找不到元数据时明确报错，不会静默回退到 `261314`。完全未传教材和章节时，为兼容旧命令，仍默认章节 `261314`、教材 `260617`。

默认是无头模式；当前站点实测部署建议使用 `--headful`。这只是浏览器显示方式，不是规避验证的方法。

### 2.3 页面和字段

当前脚本可以解析并保存：

- 教材树节点的来源 ID、父 ID、层级、类型、名称、来源路径和最近观察时间。
- 题目来源 ID、`bank_id`、详情 URL、来源短文/标题、题型和来源题型 ID。
- 难度标签、来源难度代码和精确系数，例如 `适中 (0.65)` 解析为标签 `适中`、系数 `0.65`。
- 列表/详情题干 HTML、纯文本、列表/详情/规范化内容哈希、小问数、子题数、图片/公式/表格标记。
- 页面“新题”状态、页面显示的“次组卷”次数、来源更新时间文本和可选的页面可见解答区域。
- 页面明确给出的知识点/能力标签、筛选结果出现的场景/分类等证据。
- 题图和公式图片 URL；`--download-assets` 才下载到内容寻址目录。
- 同步运行、页断点、原始页引用、错误和题目内容修订记录。

脚本对筛选条件的保存语义很重要：命令行筛选造成的题目出现记录是 `query_membership`，页面明确标出的标签/知识点是 `provider_asserted`。例如题目出现在“作业”列表，不代表供应商在题目详情中声明了“作业”标签。

### 2.4 可恢复性和安全行为

- 单浏览器、单请求队列，默认页面请求间隔 2200～3800ms；请求失败按有限次数退避。
- SQLite 开启 WAL、`busy_timeout` 和进程锁；每个完整页面在 `BEGIN IMMEDIATE` 事务中写题目、关系、标签、素材和断点。
- `--limit` 造成未完整页面时不会推进完成断点；下次运行会安全重放并依靠 `ON CONFLICT` 去重。
- 空目录合法时记录空页断点；没有题库容器、验证页或分页契约变化时熔断。
- 页面和素材 URL 做 HTTPS/允许域名检查；脚本不把本地 profile、SQLite、原始页或素材提交到代码库。

### 2.5 版本与教材元数据发现

`collector/zujuan_metadata_sync.cjs` 只发现版本和教材，不抓题目、不写 MySQL、不发布 qbpkg。默认从 `https://zujuan.xkw.com/czsx/zj261314/o2/` 进入；任意合法初中数学章节页也可作为 `--seed-url`，例如 `https://zujuan.xkw.com/czsx/zj261296/`。

```bash
cd collector
npm run sync:zujuan:metadata -- --acknowledge-source-policy --headful
npm run sync:zujuan:metadata -- --status --json-output data/zujuan-metadata.json
```

流程：等待 `#chapter_textbook_version` / `#chapter_textbooks` 加载 → 提取全部版本（`versionid`、名称原文、`new-version` → `Y/N`、DOM 顺序）→ 按页面顺序切换版本并等待教材列表签名变化 → 提取当前版本教材（`chapter-id`、名称、`grade`/`volume`）→ 逐册打开教材页并等待 `.tk-tree` 更新 → 记录真实顶级章节 ID 为 `bootstrap_chapter_external_id`。版本名称保留括号年份，例如「北师大版」和「北师大版（2012）」是两个版本。缺少稳定来源 ID 时停止，不生成名称哈希。一次未看到的历史行不会删除或停用，完整成功扫描只生成「本次未发现候选」报告。

查看数量：

```bash
npm run sync:zujuan:metadata -- --status
sqlite3 data/zujuan.sqlite3 "SELECT external_version_id, version_name, is_new FROM source_textbook_versions ORDER BY sort_order;"
sqlite3 data/zujuan.sqlite3 "SELECT version_external_id, COUNT(*) FROM source_textbooks GROUP BY version_external_id;"
```

根据教材 ID 找入口章节：

```bash
sqlite3 data/zujuan.sqlite3 "SELECT external_textbook_id, textbook_name, bootstrap_chapter_external_id FROM source_textbooks WHERE external_textbook_id = '260617';"
cd collector && npm run sync:zujuan -- --acknowledge-source-policy --textbook-id 260617 --max-pages 1 --limit 1 --headful
```

下一阶段才是整本教材目录和题目同步。当前元数据结果仍不能直接写入 MySQL 正式表。

## 3. 当前 SQLite schema

脚本实际创建的 collector 表如下：

```text
sync_runs
sync_checkpoints
textbook_nodes
questions
question_revisions
question_knowledge
question_catalog_memberships
question_facets
question_assets
source_snapshots
sync_errors
source_textbook_versions
source_textbooks
source_metadata_runs
```

`questions` 的主键是 `(provider, external_id)`；`textbook_nodes` 的主键是 `(provider, external_id)`；`source_textbook_versions` 的主键是 `(provider, external_version_id)`；`source_textbooks` 的主键是 `(provider, external_textbook_id)`，并以 `(provider, version_external_id)` 关联版本表。关系/标签/素材表使用脚本中定义的复合主键。`question_catalog_memberships` 和 `question_facets` 额外带 `query_fingerprint`，用于区分不同查询范围的证据。采集层不生成 MySQL 本地主键 `version_id` / `textbook_id`，也不写 `last_sync_batch_id`。

可以用以下命令核对当前工作区样本，而不是从本文推断运行状态：

```bash
sqlite3 data/smoke-final2.sqlite3 '.schema'
sqlite3 data/smoke-final2.sqlite3 'SELECT name, type FROM sqlite_master WHERE type IN ("table", "index") ORDER BY type, name;'
```

该 schema 是采集运行数据库，不是线上 MySQL schema，也不能直接作为发布包使用。

## 4. 采集到发布链路的边界

```text
zujuan_metadata_sync.cjs
  -> collector SQLite（source_textbook_versions / source_textbooks）
zujuan_sync.cjs
  -> collector SQLite（题目、目录、素材）
  -> collector/qbpkg.cjs build/verify（当前已实现，但 snapshot 仍是工具 schema）
  -> plugins.bank.publisher（影子表/二次校验/原子 RENAME TABLE）
  -> service/plugins/bank + pc/plugins/bank
```

当前采集器没有以下行为：

- `zujuan_sync.cjs` 本身没有 `.qbpkg` 生成选项；离线包由同一 `collector/` 工程中的 `qbpkg.cjs` 独立子命令构建。
- 不直接连接 MySQL；MySQL 写入由独立 Publisher 执行。
- 采集器不主动调用管理端或 FastAPI；管理端的一键同步由后端通过 collector API 单向编排。发布批准、正式发布和回退仍走独立批次状态及 `run-pending`。
- 没有可靠的答案/解析分栏、引用试卷数量、完整年级/学期/地区/考试字段。

qbpkg 命令见下一节，Publisher 命令见第 6 节。

## 5. qbpkg build/verify（当前已实现）

qbpkg 工具读取已经关闭的 collector SQLite，构建不可变 `.qbpkg`，包内根级必需文件为：

```text
manifest.json
snapshot.sqlite3
diff-report.json
validation.json
checksums.sha256
```

当前命令：

```bash
cd collector
npm run qbpkg:build -- --db data/zujuan.sqlite3 \
  --output data/releases/bank-2026-08-24.qbpkg \
  --metadata '{"provider":"zujuan","versionName":"北师大版","textbookName":"九年级上册","versionExternalId":"bnu","textbookExternalId":"260617","grade":"九年级","volume":"上册"}' \
  --full-snapshot \
  --range-evidence '{"scope":{"chapters":["261314"]},"completed":true}'
npm run qbpkg:verify -- --package data/releases/bank-2026-08-24.qbpkg
```

构建还支持 `--previous`、`--batch-no`、`--created-at`、`--decrease-threshold` 和 `--block-on-deactivation`。输出已存在时默认拒绝覆盖；构建在临时目录完成、自验证后再改名。snapshot schemaVersion 当前为 `2`，版本/教材外部 ID 必填，教材册次使用独立 `volume` 字段。

`snapshot.sqlite3` 只含七张工具 snapshot 表，不带采集锁、断点、运行错误和浏览器原始页表。它采用 `provider/external_id` 外部键，由 Publisher 映射 MySQL 列并复用当前正式表的本地主键。

当前验证器会拒绝缺文件、额外不安全成员、校验和篡改、SQLite 完整性/外键错误、孤儿关系、重复关系、HTML 未替换 `img src`、素材键不匹配、包内素材摘要错误以及非 NULL `reference_count`。

## 6. MySQL Publisher（当前已实现）

Publisher 位于 `service/plugins/bank/publisher`。常用入口：

```bash
cd service
python -m plugins.bank.publisher.cli verify /path/to/batch.qbpkg
python -m plugins.bank.publisher.cli register /path/to/batch.qbpkg
python -m plugins.bank.publisher.cli process <batch_id> /path/to/batch.qbpkg
python -m plugins.bank.publisher.cli run-pending --limit 10
python -m plugins.bank.publisher.cli recover
python -m plugins.bank.publisher.cli cleanup --retain-seconds 86400
```

数据库连接读取 `BANK_MYSQL_HOST/PORT/USER/PASSWORD/DATABASE`，素材根目录读取 `BANK_ASSET_ROOT`。生产环境用 Cron/systemd 周期调用 `run-pending`；管理端批准、发布和回退接口不执行 DDL。

Publisher 加载七张业务影子表和 `qb_dataset_meta` 影子表，二次校验后用同一条 `RENAME TABLE` 切换八张表；`qb_sync_batch` 不切换。旧表组短期热回退，发布包长期归档。MySQL 不自动清表，cleanup 在状态、归档摘要、保留期、锁和完整表组任一条件不满足时停止。

## 7. 字段映射重点和数据缺口

规范导出器应遵守以下映射，具体字段契约以《计划 2》为准：

| 当前 SQLite | 目标 MySQL | 规则 |
| --- | --- | --- |
| `source_textbook_versions.provider` | `qb_textbook_version.source_provider` | 固定 `zujuan`；采集器不生成 `version_id` |
| `source_textbook_versions.external_version_id` | `external_version_id` | 来源 `versionid`；缺失则阻断，不哈希名称 |
| `source_textbook_versions.version_name` | `version_name` | 页面原文，保留「（2012）」等括号年份 |
| `source_textbook_versions.is_new` | `is_new` | `new-version` → `Y`，可见但无该标记 → `N`，未知 → `NULL` |
| `source_textbook_versions.sort_order` / `status` / `last_seen_at` | 同名列 | 发现时 `status=0`；采集阶段不写 `last_sync_batch_id` |
| `source_textbooks.external_textbook_id` | `qb_textbook.external_textbook_id` | 来源 `chapter-id`；不是本地 `textbook_id` |
| `source_textbooks.version_external_id` | 由 Publisher 映射 `version_id` | 必须能关联 `source_textbook_versions` |
| `source_textbooks.textbook_name` | `textbook_name` | 页面教材名称原文 |
| `source_textbooks.grade` / `volume` | `grade` / `volume` | 从名称额外解析，例如七年级/上册、九年级/下册、全一册 |
| `source_textbooks.bootstrap_chapter_external_id` | 不进正式教材表 | 供 `zujuan_sync.cjs --textbook-id` 构造入口 URL |
| `questions.provider` | `source_provider` | 第一版为 `zujuan`，必须全包一致 |
| `questions.external_id` | `external_question_id` | 核心外部 ID 缺失时阻止自动发布，不生成名称哈希或假 ID |
| `questions.question_type` | `question_type` | 保存完整题型，不拆成互相冲突的多套列 |
| `questions.difficulty_label/ease_coefficient` | `difficulty/difficulty_coefficient` | 系数使用 DECIMAL；未知为 NULL |
| `questions.use_count` | `assemble_count` | 仅表示页面“次组卷”；**禁止映射到 `reference_count`** |
| 无可靠引用计数 | `reference_count` | 当前未采到，必须 NULL；不复制组卷次数 |
| `questions.solution_html` | `answer_html/analysis_html` | 无法可靠分栏时均 NULL，保存状态和原始证据 |
| `question_catalog_memberships` | `qb_question_catalog` | `query_catalog/query_membership` |
| `question_knowledge` | `qb_question_tag` 或可匹配的目录关系 | 页面明确知识点为 `provider_asserted` |
| `question_facets` | `qb_question_tag` | `dimension/value`；保留证据类型和查询指纹 |
| `question_assets.source_url` | `qb_question_asset` | 导出器生成稳定 `asset_key` 并重写 HTML 引用 |

素材 `asset_key` 为 `asset_type + '-' + SHA256(source_url)` 前 16 位，不依赖题目内顺序；HTML 中每个 `data-asset-key` 必须能在同题素材行找到。

## 9. 运行建议和限制

- 先用 `--max-pages 1 --limit 1` 做来源、Chrome、授权和选择器验证，再扩大目录范围。
- 增量任务可以重复扫描最新、预习、作业、典型题和压轴题；一次未看到题目不能直接删除历史采集数据或线上数据。
- 页面结构、URL 编码、robots 响应或来源授权变化时停任务并人工检查，不为绕过验证而修改限速和熔断。
- `--include-visible-solutions` 只保存当前页面已公开渲染的内容；它不登录、不绕过权限，也不能把结果自动当成结构化答案/解析。
- 原始页和素材包含第三方内容，必须按授权范围、访问控制和保留策略管理。
